## 💻 Code Standard: Arrow Functions Over Function Declarations

### 🎯 Objective

To maintain consistency, improve code readability, and leverage modern JavaScript best practices by using arrow functions (`=>`) instead of traditional function declarations (`function`) throughout the codebase. Arrow functions provide lexical `this` binding, more concise syntax, and align with modern JavaScript/TypeScript conventions.

### 📜 Rule Details

1.  **Universal Application:** This rule applies to all function definitions including standalone functions, utility functions, callback functions, and methods within objects.
2.  **Const Declaration:** Arrow functions must be assigned to `const` variables to prevent reassignment.
3.  **Naming Convention:**
    - Regular functions and utilities should use **camelCase** (e.g., `calculateTotal`, `fetchUserData`)
    - React components should use **PascalCase** (e.g., `UserCard`, `NavigationBar`)
    - Event handlers and callbacks within components should use **camelCase** with the **`handle` prefix** (e.g., `handleClick`, `handleSubmit`, `handleInputChange`)
4.  **Export Pattern:** For exported functions, use `export const` rather than `export function`.

### ✅ Required Code Snippets (The "Do")

#### 1\. Standalone Utility Function

Use arrow functions with const and camelCase for all utility functions.

```typescript
// ✅ DO: Use arrow function with const declaration and camelCase
// File: calculate-total.util.ts

type CalculateTotalArgs = {
  items: number[];
  taxRate: number;
};

export const calculateTotal = ({ items, taxRate }: CalculateTotalArgs): number => {
  const subtotal = items.reduce((sum, item) => sum + item, 0);
  return subtotal * (1 + taxRate);
};
```

#### 2\. React Component

React components should always use arrow function syntax with PascalCase naming.

```typescript
// ✅ DO: Use arrow function for React components with PascalCase
// File: UserCard.tsx

import type { UserCardProps } from './UserCard.types';

export const UserCard = ({ name, email, avatar }: UserCardProps) => {
  return (
    <div className="user-card">
      <img src={avatar} alt={name} />
      <h3>{name}</h3>
      <p>{email}</p>
    </div>
  );
};
```

#### 3\. Event Handlers and Callbacks

Event handlers and callbacks should use arrow functions with camelCase and the `handle` prefix.

```typescript
// ✅ DO: Use arrow functions for event handlers with 'handle' prefix
// File: LoginForm.tsx

import { useState } from 'react';
import type { LoginFormProps } from './LoginForm.types';

export const LoginForm = ({ onSubmit }: LoginFormProps) => {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');

  const handleEmailChange = (event: React.ChangeEvent<HTMLInputElement>) => {
    setEmail(event.target.value);
  };

  const handlePasswordChange = (event: React.ChangeEvent<HTMLInputElement>) => {
    setPassword(event.target.value);
  };

  const handleSubmit = (event: React.FormEvent) => {
    event.preventDefault();
    onSubmit({ email, password });
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email}
        onChange={handleEmailChange}
        placeholder="Email"
      />
      <input
        type="password"
        value={password}
        onChange={handlePasswordChange}
        placeholder="Password"
      />
      <button type="submit">Login</button>
    </form>
  );
};
```

#### 4\. Object Methods

Even within objects, prefer arrow functions with camelCase for consistency.

```typescript
// ✅ DO: Use arrow functions for object methods with camelCase
// File: user-service.ts

type CreateUserArgs = {
  name: string;
  email: string;
};

type UpdateUserArgs = {
  id: string;
  data: Partial<User>;
};

export const userService = {
  createUser: ({ name, email }: CreateUserArgs) => {
    // Create user logic
    return { id: '123', name, email };
  },

  updateUser: ({ id, data }: UpdateUserArgs) => {
    // Update user logic
    return { id, ...data };
  },

  deleteUser: (id: string) => {
    // Delete user logic
    console.log(`Deleting user ${id}`);
  },
};
```

#### 5\. Array Methods and Callbacks

Arrow functions are especially concise for array operations, using camelCase.

```typescript
// ✅ DO: Use arrow functions for array methods with camelCase
// File: filter-users.util.ts

type User = {
  id: string;
  name: string;
  active: boolean;
};

export const filterActiveUsers = (users: User[]): User[] => {
  return users
    .filter((user) => user.active)
    .map((user) => ({ ...user, name: user.name.toUpperCase() }))
    .sort((a, b) => a.name.localeCompare(b.name));
};
```

#### 6\. Async Functions

Async arrow functions maintain the same pattern with camelCase.

```typescript
// ✅ DO: Use async arrow functions with camelCase
// File: fetch-user.util.ts

type FetchUserArgs = {
  userId: string;
  includeProfile: boolean;
};

export const fetchUser = async ({ userId, includeProfile }: FetchUserArgs): Promise<User> => {
  const response = await fetch(`/api/users/${userId}`);
  const user = await response.json();

  if (includeProfile) {
    user.profile = await fetchUserProfile(userId);
  }

  return user;
};

const fetchUserProfile = async (userId: string): Promise<UserProfile> => {
  const response = await fetch(`/api/users/${userId}/profile`);
  return response.json();
};
```

#### 7\. Higher-Order Functions

Arrow functions work seamlessly for functions that return functions, using camelCase.

```typescript
// ✅ DO: Use arrow functions for higher-order functions with camelCase
// File: create-logger.util.ts

type CreateLoggerArgs = {
  prefix: string;
  level: 'info' | 'warn' | 'error';
};

export const createLogger = ({ prefix, level }: CreateLoggerArgs) => {
  return (message: string) => {
    console[level](`[${prefix}] ${message}`);
  };
};

// Usage
const errorLogger = createLogger({ prefix: 'API', level: 'error' });
errorLogger('Failed to fetch data');
```

#### 8\. Complex Component with Multiple Handlers

Demonstrating proper naming for components (PascalCase) and handlers (camelCase with `handle` prefix).

```typescript
// ✅ DO: PascalCase for component, camelCase with 'handle' prefix for handlers
// File: ProductCard.tsx

import { useState } from 'react';
import type { ProductCardProps } from './ProductCard.types';

export const ProductCard = ({
  product,
  onAddToCart,
  onViewDetails
}: ProductCardProps) => {
  const [quantity, setQuantity] = useState(1);

  const handleQuantityIncrease = () => {
    setQuantity((prev) => prev + 1);
  };

  const handleQuantityDecrease = () => {
    setQuantity((prev) => Math.max(1, prev - 1));
  };

  const handleAddToCart = () => {
    onAddToCart({ productId: product.id, quantity });
  };

  const handleViewDetails = () => {
    onViewDetails(product.id);
  };

  return (
    <div className="product-card">
      <h3>{product.name}</h3>
      <p>${product.price}</p>
      <div>
        <button onClick={handleQuantityDecrease}>-</button>
        <span>{quantity}</span>
        <button onClick={handleQuantityIncrease}>+</button>
      </div>
      <button onClick={handleAddToCart}>Add to Cart</button>
      <button onClick={handleViewDetails}>View Details</button>
    </div>
  );
};
```

### ❌ Forbidden Code Snippets (The "Don't")

#### 1\. Traditional Function Declaration

Function declarations are not allowed. Always use arrow functions with const.

```typescript
// ❌ DON'T: Use function declaration
function calculateTotal(items: number[], taxRate: number): number {
  const subtotal = items.reduce((sum, item) => sum + item, 0);
  return subtotal * (1 + taxRate);
}

// ❌ DON'T: Use function declaration for exports
export function processData(data: string): string {
  return data.toUpperCase();
}

// ❌ DON'T: Use function declaration for React components
function UserCard({ name, email }: UserCardProps) {
  return <div>{name}</div>;
}
```

#### 2\. Wrong Naming Convention

Components must use PascalCase, utilities must use camelCase, and handlers must have `handle` prefix.

```typescript
// ❌ DON'T: Use camelCase for React components
export const userCard = ({ name, email }: UserCardProps) => {
  return <div>{name}</div>;
};

// ❌ DON'T: Use PascalCase for utility functions
export const CalculateTotal = ({ items, taxRate }: CalculateTotalArgs): number => {
  return items.reduce((sum, item) => sum + item, 0) * (1 + taxRate);
};

// ❌ DON'T: Omit 'handle' prefix for event handlers
export const LoginForm = ({ onSubmit }: LoginFormProps) => {
  const submitForm = (event: React.FormEvent) => {  // Should be handleSubmit
    event.preventDefault();
  };

  const onClick = () => {  // Should be handleClick
    console.log('clicked');
  };

  return <form onSubmit={submitForm}>{/* ... */}</form>;
};
```

#### 3\. Function Expression with `function` Keyword

Even when assigning to a variable, avoid the `function` keyword.

```typescript
// ❌ DON'T: Use function expression with function keyword
const calculateTotal = function(items: number[], taxRate: number): number {
  const subtotal = items.reduce((sum, item) => sum + item, 0);
  return subtotal * (1 + taxRate);
};

// ❌ DON'T: Use function keyword for React components
const UserCard = function({ name, email }: UserCardProps) {
  return <div>{name}</div>;
};
```

#### 4\. React Class Components with Methods

Avoid class components with method declarations. Use functional components with arrow functions.

```typescript
// ❌ DON'T: Use class components with method declarations
import React from 'react';

class UserCard extends React.Component<UserCardProps> {
  handleClick() {  // Problematic: needs .bind(this) or arrow in constructor
    console.log(this.props.name);
  }

  render() {
    return <button onClick={this.handleClick}>Click</button>;
  }
}
```

#### 5\. Object Method Shorthand (Without Arrow)

While method shorthand is valid JavaScript, arrow functions are preferred for consistency.

```typescript
// ❌ DON'T: Use object method shorthand syntax
export const userService = {
  // This shorthand doesn't use arrow functions
  createUser(name: string, email: string) {
    return { id: '123', name, email };
  },

  updateUser(id: string, data: object) {
    return { id, ...data };
  },
};
```

#### 6\. Non-Const Arrow Functions

Arrow functions must be assigned to `const` to prevent reassignment.

```typescript
// ❌ DON'T: Use let or var with arrow functions
let calculateTotal = (items: number[]): number => {
  return items.reduce((sum, item) => sum + item, 0);
};

// ❌ DON'T: This allows dangerous reassignment
calculateTotal = (items: number[]): number => {
  return 0; // Function logic completely changed!
};
```

#### 7\. Generator Functions

While generator functions require the `function*` syntax, they should be avoided in favor of async/await patterns when possible.

```typescript
// ❌ DON'T: Use generator functions (prefer async/await)
function* numberGenerator() {
  yield 1;
  yield 2;
  yield 3;
}

// ✅ DO: Use async iterators or async/await patterns instead
const generateNumbers = async function* () {
  yield 1;
  yield 2;
  yield 3;
};
```

#### 8\. Named Function Expressions

Named function expressions for recursion should use arrow functions assigned to const.

```typescript
// ❌ DON'T: Use named function expression
const factorial = function factorial(n: number): number {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
};

// ✅ DO: Use arrow function (const name allows recursion)
const factorial = (n: number): number => {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
};
```

### 📝 Summary of Dos and Don'ts

#### ✅ DO:

- Always use arrow functions (`=>`) for all function definitions
- Assign arrow functions to `const` variables to prevent reassignment
- Use **camelCase** for utility functions and regular functions (e.g., `calculateTotal`, `fetchUser`)
- Use **PascalCase** for React components (e.g., `UserCard`, `NavigationBar`)
- Use **camelCase with `handle` prefix** for event handlers and callbacks (e.g., `handleClick`, `handleSubmit`)
- Use arrow functions for utility functions, React components, and callbacks
- Use arrow functions for object methods and event handlers
- Use arrow functions for array methods and higher-order functions
- Export functions using `export const functionName = () => {}`
- Use async arrow functions for asynchronous operations
- Maintain consistent arrow function usage across the entire codebase

#### ❌ DON'T:

- Use traditional function declarations (`function name() {}`)
- Use function expressions with the `function` keyword
- Use class components with method declarations (use functional components)
- Use object method shorthand syntax (prefer explicit arrow functions)
- Assign arrow functions to `let` or `var` (always use `const`)
- Use named function expressions for recursion (const name works fine)
- Mix function declaration styles within the same codebase
- Use generator functions when async/await patterns can be used instead
- Use camelCase for React components (must be PascalCase)
- Use PascalCase for utility functions (must be camelCase)
- Omit the `handle` prefix for event handlers in components

### 🎯 Quick Reference: Arrow Function Patterns

| Use Case         | Naming Convention    | Pattern                         | Example                                                                  |
| ---------------- | -------------------- | ------------------------------- | ------------------------------------------------------------------------ |
| Utility Function | camelCase            | `const name = () => {}`         | `const calculateSum = (nums: number[]) => nums.reduce((a, b) => a + b);` |
| React Component  | PascalCase           | `const Name = (props) => {}`    | `const Button = ({ label }: ButtonProps) => <button>{label}</button>;`   |
| Event Handler    | camelCase + `handle` | `const handleX = (e) => {}`     | `const handleClick = (e: MouseEvent) => console.log(e);`                 |
| Async Function   | camelCase            | `const name = async () => {}`   | `const fetchData = async () => await api.get();`                         |
| Array Callback   | camelCase            | `.map(item => {})`              | `users.map(user => user.name)`                                           |
| Object Method    | camelCase            | `{ method: () => {} }`          | `{ saveData: (data: Data) => storage.save(data) }`                       |
| Higher-Order     | camelCase            | `const create = () => () => {}` | `const createLogger = (prefix: string) => (msg: string) => log(msg);`    |

### 🔍 Benefits of Arrow Functions

1. **Lexical `this` Binding:** Arrow functions inherit `this` from their enclosing scope, eliminating the need for `.bind(this)` or storing `this` in variables.
2. **Concise Syntax:** Shorter, more readable code, especially for simple functions and callbacks.
3. **Consistency:** Using arrow functions everywhere creates a uniform codebase style.
4. **Modern Standard:** Arrow functions are the modern JavaScript/TypeScript standard and align with current best practices.
5. **No Hoisting Confusion:** Unlike function declarations, arrow functions with `const` are not hoisted, making code flow more predictable.
6. **Immutability:** Using `const` prevents accidental function reassignment, reducing bugs.
7. **Clear Naming Conventions:** PascalCase for components and camelCase for functions makes code intent immediately clear.
