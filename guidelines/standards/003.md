## 💻 Code Standard: File Type Distinctions and Usage

### 🎯 Objective

To establish clear guidelines for when to use `.constants.ts`, `.config.ts`, `.util.ts`, and `.helper.ts` files. This standard ensures that code is organized logically, making it easier for developers to locate functionality, understand dependencies, and maintain consistency across the codebase.

### 📜 Rule Details

1.  **Constants Files (`.constants.ts`)**: Used for immutable, hard-coded values that never change at runtime. These are compile-time values used in business logic, validation, or component behavior.
2.  **Config Files (`.config.ts`)**: Used for application-wide configuration settings that may vary by environment (development, staging, production). These often read from environment variables.
3.  **Utility Files (`.util.ts`)**: Used for pure, general-purpose functions that perform data transformation or computation without side effects. These functions are domain-agnostic and reusable across the entire application.
4.  **Helper Files (`.helper.ts`)**: Used for domain-specific or feature-specific business logic that may compose multiple utilities, have side effects, or depend on application context.

### 📋 Detailed Definitions

#### `.constants.ts` - Immutable Values

- **What**: Hard-coded values, magic numbers, enums, lookup tables
- **Scope**: Component-specific or feature-specific
- **Mutability**: Never changes at runtime
- **Dependencies**: No external dependencies
- **Side Effects**: None
- **When to use**: When you need to define fixed values used in business logic

#### `.config.ts` - Configuration Settings

- **What**: Application settings, API endpoints, feature flags, environment-specific values
- **Scope**: Application-wide or module-wide
- **Mutability**: Can vary by environment
- **Dependencies**: Often reads from `process.env`
- **Side Effects**: May read environment variables
- **When to use**: When settings need to change based on environment or deployment

#### `.util.ts` - Pure Utility Functions

- **What**: Generic, reusable functions for data transformation
- **Scope**: General-purpose, domain-agnostic
- **Mutability**: Pure functions (same input → same output)
- **Dependencies**: Minimal, no application context
- **Side Effects**: None (pure functions)
- **When to use**: For generic operations like formatting, validation, calculations

#### `.helper.ts` - Business Logic Functions

- **What**: Domain-specific business logic, feature-specific operations
- **Scope**: Feature or domain-specific
- **Mutability**: May have side effects
- **Dependencies**: Often composes utilities, uses constants/config
- **Side Effects**: Possible (API calls, state changes, etc.)
- **When to use**: For feature-specific logic that orchestrates multiple operations

```typescript
export const formatDate = (date: Date, format: string = 'YYYY-MM-DD'): string => {
  const year = date.getFullYear();
  const month = String(date.getMonth() + 1).padStart(2, '0');
  const day = String(date.getDate()).padStart(2, '0');

  return format.replace('YYYY', String(year)).replace('MM', month).replace('DD', day);
};

export const addDays = (date: Date, days: number): Date => {
  const result = new Date(date);
  result.setDate(result.getDate() + days);
  return result;
};

export const subtractDays = (date: Date, days: number): Date => {
  return addDays(date, -days);
};

export const getDaysDifference = (date1: Date, date2: Date): number => {
  const oneDay = 24 * 60 * 60 * 1000;
  return Math.round((date1.getTime() - date2.getTime()) / oneDay);
};

export const isWeekend = (date: Date): boolean => {
  const day = date.getDay();
  return day === 0 || day === 6;
};

export const getStartOfDay = (date: Date): Date => {
  const result = new Date(date);
  result.setHours(0, 0, 0, 0);
  return result;
};
```

```typescript
export const capitalize = (str: string): string => {
  if (!str) return '';
  return str.charAt(0).toUpperCase() + str.slice(1).toLowerCase();
};

export const capitalizeWords = (str: string): string => {
  return str.split(' ').map(capitalize).join(' ');
};

export const truncate = (str: string, maxLength: number, suffix: string = '...'): string => {
  if (str.length <= maxLength) return str;
  return str.slice(0, maxLength - suffix.length) + suffix;
};

export const slugify = (str: string): string => {
  return str
    .toLowerCase()
    .trim()
    .replace(/[^\w\s-]/g, '')
    .replace(/[\s_-]+/g, '-')
    .replace(/^-+|-+$/g, '');
};

export const camelToKebab = (str: string): string => {
```

```typescript
export const chunk = <T>(array: T[], size: number): T[][] => {
  const chunks: T[][] = [];
  for (let i = 0; i < array.length; i += size) {
    chunks.push(array.slice(i, i + size));
  }
  return chunks;
};

export const unique = <T>(array: T[]): T[] => {
  return Array.from(new Set(array));
};

export const uniqueBy = <T>(array: T[], key: keyof T): T[] => {
  const seen = new Set();
  return array.filter((item) => {
    const value = item[key];
    if (seen.has(value)) return false;
    seen.add(value);
    return true;
  });
};

export const groupBy = <T>(array: T[], key: keyof T): Record<string, T[]> => {
  return array.reduce(
    (result, item) => {
      const groupKey = String(item[key]);
      if (!result[groupKey]) {
        result[groupKey] = [];
      }
      result[groupKey].push(item);
      return result;
    },
    {} as Record<string, T[]>,
  );
};

export const sortBy = <T>(array: T[], key: keyof T, order: 'asc' | 'desc' = 'asc'): T[] => {
  return [...array].sort((a, b) => {
    const aVal = a[key];
    const bVal = b[key];
    if (aVal < bVal) return order === 'asc' ? -1 : 1;
    if (aVal > bVal) return order === 'asc' ? 1 : -1;
    return 0;
  });
};
```

```typescript
// ✅ DO: Create domain-specific helper for user validation
// File: user-validation.helper.ts

import {
  EMAIL_REGEX,
  PASSWORD_REGEX,
  MIN_PASSWORD_LENGTH,
  MAX_PASSWORD_LENGTH,
  ERROR_MESSAGES,
} from './validation.constants';
import { removeWhitespace } from '../utils/string-manipulation.util';

type ValidateUserRegistrationArgs = {
  email: string;
  password: string;
  confirmPassword: string;
  username: string;
  age: number;
  termsAccepted: boolean;
};

type ValidationResult = {
  isValid: boolean;
  errors: Record<string, string[]>;
};

export const validateUserRegistration = ({
  email,
  password,
  confirmPassword,
  username,
  age,
  termsAccepted,
}: ValidateUserRegistrationArgs): ValidationResult => {
  const errors: Record<string, string[]> = {};

  // Email validation
  if (!email) {
    errors.email = [ERROR_MESSAGES.REQUIRED];
  } else if (!EMAIL_REGEX.test(email)) {
    errors.email = [ERROR_MESSAGES.INVALID_EMAIL];
  }

  // Password validation
  if (!password) {
    errors.password = [ERROR_MESSAGES.REQUIRED];
  } else {
    const passwordErrors: string[] = [];

    if (password.length < MIN_PASSWORD_LENGTH) {
      passwordErrors.push(ERROR_MESSAGES.PASSWORD_TOO_SHORT);
    }

    if (password.length > MAX_PASSWORD_LENGTH) {
      passwordErrors.push(ERROR_MESSAGES.PASSWORD_TOO_LONG);
    }

    if (!PASSWORD_REGEX.test(password)) {
      passwordErrors.push(ERROR_MESSAGES.PASSWORD_WEAK);
    }

    if (passwordErrors.length > 0) {
      errors.password = passwordErrors;
    }
  }

  // Confirm password validation
  if (password !== confirmPassword) {
    errors.confirmPassword = ['Passwords do not match'];
  }

  // Username validation
  const cleanUsername = removeWhitespace(username);
  if (!cleanUsername) {
    errors.username = [ERROR_MESSAGES.REQUIRED];
  } else if (!/^[a-zA-Z0-9_]+$/.test(cleanUsername)) {
    errors.username = [ERROR_MESSAGES.USERNAME_INVALID];
  }

  // Age validation
  if (age < 18) {
    errors.age = ['You must be at least 18 years old to register'];
  }

  // Terms validation
  if (!termsAccepted) {
    errors.terms = ['You must accept the terms and conditions'];
  }

  return {
    isValid: Object.keys(errors).length === 0,
    errors,
  };
};

export const validateEmail = (email: string): boolean => {
  return EMAIL_REGEX.test(email);
};

export const validatePasswordStrength = (
  password: string,
): {
  isStrong: boolean;
  score: number;
  feedback: string[];
} => {
  const feedback: string[] = [];
  let score = 0;

  if (password.length >= MIN_PASSWORD_LENGTH) score++;
  if (password.length >= 12) score++;
  if (/[a-z]/.test(password)) score++;
  if (/[A-Z]/.test(password)) score++;
  if (/\d/.test(password)) score++;
  if (/[@$!%*?&]/.test(password)) score++;

  if (score < 3) feedback.push('Password is too weak');
  if (!/[a-z]/.test(password)) feedback.push('Add lowercase letters');
  if (!/[A-Z]/.test(password)) feedback.push('Add uppercase letters');
  if (!/\d/.test(password)) feedback.push('Add numbers');
  if (!/[@$!%*?&]/.test(password)) feedback.push('Add special characters');

  return {
    isStrong: score >= 4,
    score,
    feedback,
  };
};
```

```typescript
// ✅ DO: Create domain-specific helper for cart calculations
// File: cart-calculation.helper.ts

import { TAX_RATES, DISCOUNT_TYPES, FREE_SHIPPING_THRESHOLD } from './pricing.constants';
import { roundToDecimals } from '../utils/number-operations.util';
import { formatCurrency } from '../utils/format-currency.util';

type CartItem = {
  id: string;
  name: string;
  price: number;
  quantity: number;
  taxRate: keyof typeof TAX_RATES;
};

type Discount = {
  code: string;
  type: keyof typeof DISCOUNT_TYPES;
  value: number;
};

type CalculateCartTotalArgs = {
  items: CartItem[];
  discount?: Discount;
  shippingCost?: number;
};

type CartTotal = {
  subtotal: number;
  subtotalFormatted: string;
  discountAmount: number;
  discountAmountFormatted: string;
  taxAmount: number;
  taxAmountFormatted: string;
  shippingCost: number;
  shippingCostFormatted: string;
  total: number;
  totalFormatted: string;
  isFreeShipping: boolean;
};

export const calculateCartTotal = ({
  items,
  discount,
  shippingCost = 0,
}: CalculateCartTotalArgs): CartTotal => {
  // Calculate subtotal
  const subtotal = items.reduce((sum, item) => {
    return sum + item.price * item.quantity;
  }, 0);

  // Calculate discount
  let discountAmount = 0;
  if (discount) {
    if (discount.type === DISCOUNT_TYPES.PERCENTAGE) {
      discountAmount = subtotal * (discount.value / 100);
    } else if (discount.type === DISCOUNT_TYPES.FIXED_AMOUNT) {
      discountAmount = Math.min(discount.value, subtotal);
    }
  }

  const afterDiscount = subtotal - discountAmount;

  // Calculate tax per item (after discount applied proportionally)
  const taxAmount = items.reduce((sum, item) => {
    const itemTotal = item.price * item.quantity;
    const itemAfterDiscount = itemTotal * (afterDiscount / subtotal);
    const taxRate = TAX_RATES[item.taxRate];
    return sum + itemAfterDiscount * taxRate;
  }, 0);

  // Determine if free shipping applies
  const isFreeShipping = subtotal >= FREE_SHIPPING_THRESHOLD;
  const finalShippingCost = isFreeShipping ? 0 : shippingCost;

  // Calculate total
  const total = afterDiscount + taxAmount + finalShippingCost;

  return {
    subtotal: roundToDecimals(subtotal, 2),
    subtotalFormatted: formatCurrency(subtotal),
    discountAmount: roundToDecimals(discountAmount, 2),
    discountAmountFormatted: formatCurrency(discountAmount),
    taxAmount: roundToDecimals(taxAmount, 2),
    taxAmountFormatted: formatCurrency(taxAmount),
    shippingCost: roundToDecimals(finalShippingCost, 2),
    shippingCostFormatted: formatCurrency(finalShippingCost),
    total: roundToDecimals(total, 2),
    totalFormatted: formatCurrency(total),
    isFreeShipping,
  };
};

export const calculateItemDiscount = (
  originalPrice: number,
  discountPercentage: number,
): number => {
  return roundToDecimals(originalPrice * (discountPercentage / 100), 2);
};

export const calculateFinalPrice = (originalPrice: number, discountPercentage: number): number => {
  const discount = calculateItemDiscount(originalPrice, discountPercentage);
  return roundToDecimals(originalPrice - discount, 2);
};
```

```typescript
  formData: {

    password: string;
    confirmPassword: string;

    termsAccepted: boolean;
  };

export const submitRegistrationForm = async ({
  formData,
  onSuccess,
  onError,
}: SubmitRegistrationFormArgs): Promise<void> => {
  // Validate form data
  const validation = validateUserRegistration(formData);

  if (!validation.isValid) {
    onError(validation.errors);
    return;
  }

  try {
    // Submit to API
    const response = await fetch(`${apiConfig.baseUrl}${apiConfig.endpoints.auth.register}`, {
      method: 'POST',
      headers: apiConfig.headers,
      body: JSON.stringify({
        email: formData.email,
        password: formData.password,
        username: formData.username,
        age: formData.age,
      }),
    });

    if (!response.ok) {
      const errorData = await response.json();
      onError(errorData.errors || { general: ['Registration failed'] });
      return;
    }

    const data = await response.json();
    onSuccess(data.userId);
  } catch (error) {
    onError({ general: ['An unexpected error occurred. Please try again.'] });
  }
};
```

```typescript
// File: product-transformation.helper.ts

import { formatCurrency } from '../utils/format-currency.util';
import { capitalize } from '../utils/string-manipulation.util';
import { roundToDecimals } from '../utils/number-operations.util';

type RawProduct = {
  id: string;
  name: string;
  price: number;
  discount_percentage: number;
  category: string;
  in_stock: boolean;
  image_url: string;
};

type TransformedProduct = {
  id: string;
  name: string;
  category: string;
  price: {
    original: number;
    originalFormatted: string;
    discount: number;
    discountFormatted: string;
    final: number;
    finalFormatted: string;
  };
  availability: {
    inStock: boolean;
    status: string;
  };
  imageUrl: string;
};

export const transformProduct = (rawProduct: RawProduct): TransformedProduct => {
  const discountAmount = roundToDecimals(
    rawProduct.price * (rawProduct.discount_percentage / 100),
    2,
  );

  const finalPrice = roundToDecimals(rawProduct.price - discountAmount, 2);

  return {
    id: rawProduct.id,
    name: capitalize(rawProduct.name),
    category: capitalize(rawProduct.category),
    price: {
      original: rawProduct.price,
      originalFormatted: formatCurrency(rawProduct.price),
      discount: discountAmount,
      discountFormatted: formatCurrency(discountAmount),
      final: finalPrice,
      finalFormatted: formatCurrency(finalPrice),
    },
    availability: {
      inStock: rawProduct.in_stock,
      status: rawProduct.in_stock ? 'In Stock' : 'Out of Stock',
    },
    imageUrl: rawProduct.image_url,
  };
};

export const transformProducts = (rawProducts: RawProduct[]): TransformedProduct[] => {
  return rawProducts.map(transformProduct);
};

export const filterProductsByCategory = (
  products: TransformedProduct[],
  category: string,
): TransformedProduct[] => {
  return products.filter((product) => product.category.toLowerCase() === category.toLowerCase());
};

export const sortProductsByPrice = (
  products: TransformedProduct[],
  order: 'asc' | 'desc' = 'asc',
): TransformedProduct[] => {
  return [...products].sort((a, b) => {
    const comparison = a.price.final - b.price.final;
    return order === 'asc' ? comparison : -comparison;
  });
};
```

### ❌ Forbidden Code Snippets (The "Don't")

#### 1\. Don't Put Configuration in Constants Files

Configuration that varies by environment should not be in constants files.

```typescript
// ❌ DON'T: Put environment-specific config in constants file
// File: api.constants.ts

export const API_BASE_URL = 'https://api.example.com'; // This should be in config!
export const API_TIMEOUT = 30000;
export const API_KEY = 'abc123'; // Never hardcode sensitive data!

// This is environment-specific and should read from process.env
```

```typescript
// ✅ DO: Put environment-specific config in config file
// File: api.config.ts

export const apiConfig = {
  baseUrl: process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3001',
  timeout: 30000,
  // Never include API keys in code - use environment variables
  apiKey: process.env.API_KEY,
};
```

#### 2\. Don't Put Pure Utilities in Helper Files

Generic, reusable functions should not be in helper files.

```typescript
// ❌ DON'T: Put pure utilities in helper files
// File: cart-calculation.helper.ts

// This is a pure utility and should be in a .util.ts file
export const formatCurrency = (amount: number): string => {
  return new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: 'USD',
  }).format(amount);
};
// This is also a pure utility
export const roundToDecimals = (value: number, decimals: number): number => {
  const factor = Math.pow(10, decimals);
  return Math.round(value * factor) / factor;
};
// This is domain-specific and belongs here
export const calculateCartTotal = ({ items, taxRate }: CalculateCartTotalArgs) => {
  // ... business logic
};
```

```typescript
// ✅ DO: Separate pure utilities from domain logic
// File: format-currency.util.ts
export const formatCurrency = (amount: number): string => {
  return new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: 'USD',
  }).format(amount);
};

// File: number-operations.util.ts
export const roundToDecimals = (value: number, decimals: number): number => {
  const factor = Math.pow(10, decimals);

};

import { formatCurrency } from '../utils/format-currency.util';
import { roundToDecimals } from '../utils/number-operations.util';

export const calculateCartTotal = ({ items, taxRate }: CalculateCartTotalArgs) => {
  // ... business logic using the utilities
};
```

#### 3\. Don't Put Business Logic in Utility Files

Domain-specific business logic should not be in utility files.

```typescript
// ❌ DON'T: Put business logic in utility files
// File: date-operations.util.ts

import { apiConfig } from '../config/api.config';

// This is NOT a pure utility - it has business logic and side effects
export const fetchUserBirthday = async (userId: string): Promise<Date> => {
  const response = await fetch(`${apiConfig.baseUrl}/users/${userId}/birthday`);
  const data = await response.json();
  return new Date(data.birthday);
};

// This has business rules (18 years) and should be in a helper
export const isUserAdult = (birthDate: Date): boolean => {
  const today = new Date();
  const age = today.getFullYear() - birthDate.getFullYear();
  return age >= 18;
};
```

```typescript
// ✅ DO: Keep utilities pure, move business logic to helpers
// File: date-operations.util.ts (pure utilities)

export const getAge = (birthDate: Date): number => {
  const today = new Date();
  let age = today.getFullYear() - birthDate.getFullYear();
  const monthDiff = today.getMonth() - birthDate.getMonth();

  if (monthDiff < 0 || (monthDiff === 0 && today.getDate() < birthDate.getDate())) {
    age--;
  }

  return age;
};

export const addYears = (date: Date, years: number): Date => {
  const result = new Date(date);
  result.setFullYear(result.getFullYear() + years);
  return result;
};

// File: user-validation.helper.ts (business logic)
import { getAge } from '../utils/date-operations.util';
import { MIN_USER_AGE } from './user.constants';

export const isUserAdult = (birthDate: Date): boolean => {
  const age = getAge(birthDate);
  return age >= MIN_USER_AGE;
};

export const fetchAndValidateUserAge = async (userId: string): Promise<boolean> => {
  // Business logic with side effects
  const response = await fetch(`${apiConfig.baseUrl}/users/${userId}`);
  const data = await response.json();
  return isUserAdult(new Date(data.birthDate));
};
```

#### 5\. Don't Hardcode Magic Numbers

Magic numbers should be extracted to constants with descriptive names.

```typescript
// ❌ DON'T: Use magic numbers in business logic
// File: user-validation.helper.ts

export const isUserAdult = (age: number): boolean => {
  return age >= 18; // What does 18 mean? Why 18?
};

export const isPasswordValid = (password: string): boolean => {
  return password.length >= 8 && password.length <= 128; // Magic numbers!
};

export const canUserComment = (accountAge: number): boolean => {
  return accountAge >= 7; // 7 what? Days? Weeks?
};
```

```typescript
// ✅ DO: Extract magic numbers to constants
// File: user.constants.ts

export const MIN_USER_AGE = 18;
export const MIN_PASSWORD_LENGTH = 8;
export const MAX_PASSWORD_LENGTH = 128;
export const MIN_ACCOUNT_AGE_DAYS = 7;

// File: user-validation.helper.ts
import {
  MIN_USER_AGE,
  MIN_PASSWORD_LENGTH,
  MAX_PASSWORD_LENGTH,
  MIN_ACCOUNT_AGE_DAYS,
} from './user.constants';

  return age >= MIN_USER_AGE;
```

#### 7\. Don't Create Helper Functions Without Clear Domain Purpose

If a function is generic enough to be reused anywhere, it should be a utility.

```typescript
// ❌ DON'T: Create helpers for generic operations
// File: string-helpers.helper.ts

// These are generic utilities, not domain-specific helpers!
export const capitalize = (str: string): string => {
  return str.charAt(0).toUpperCase() + str.slice(1);
};

export const truncate = (str: string, length: number): string => {
  return str.length > length ? str.slice(0, length) + '...' : str;
};

// File should be named string-manipulation.util.ts instead
```

```typescript
// ✅ DO: Use helpers only for domain-specific logic
// File: string-manipulation.util.ts (utilities)
export const capitalize = (str: string): string => {
  return str.charAt(0).toUpperCase() + str.slice(1);
};

export const truncate = (str: string, length: number): string => {
  return str.length > length ? str.slice(0, length) + '...' : str;
};

// File: product-display.helper.ts (domain logic)
import { capitalize } from '../utils/string-manipulation.util';
import { MAX_PRODUCT_NAME_LENGTH } from './product.constants';

export const formatProductName = (name: string, includeCategory: boolean): string => {
  let formatted = capitalize(name);

  if (formatted.length > MAX_PRODUCT_NAME_LENGTH) {
    formatted = formatted.slice(0, MAX_PRODUCT_NAME_LENGTH) + '...';
  }

  if (includeCategory) {
    // Business logic specific to product display
    formatted = `[Category] ${formatted}`;
  }

  return formatted;
};
```

### 📝 Summary of Dos and Don'ts

#### ✅ DO:

**Constants (`.constants.ts`)**

- Use for immutable, hard-coded values
- Keep component constants with their components
- Extract magic numbers to named constants
- Use `as const` for object constants to ensure immutability
- Name constants in SCREAMING_SNAKE_CASE for primitive values

**Config (`.config.ts`)**

- Use for environment-dependent settings
- Read from `process.env` for values that vary by environment
- Keep config at application or module level
- Group related configuration together (API, analytics, features)
- Never hardcode sensitive data (API keys, secrets)

**Utils (`.util.ts`)**

- Create pure functions with no side effects
- Keep functions generic and reusable across the application
- Test utilities thoroughly (they should be deterministic)
- Avoid dependencies on application context
- Focus on data transformation and computation

**Helpers (`.helper.ts`)**

- Use for domain-specific business logic
- Compose multiple utilities to implement features
- May have side effects (API calls, state changes)
- Can depend on constants, config, and utilities
- Focus on orchestrating business rules

#### ❌ DON'T:

**General**

- Don't mix file types (constants in config, utilities in helpers, etc.)
- Don't put business logic in utilities
- Don't put pure functions in helpers
- Don't hardcode values that should be constants
- Don't put environment-specific values in constants
- Don't create overly generic files mixing multiple concerns

**Constants**

- Don't use `process.env` in constants files
- Don't put API keys or secrets in constants
- Don't mix component-specific and shared constants
- Don't use constants for values that change at runtime

**Config**

- Don't hardcode environment-specific values
- Don't put business rules in config
- Don't mix config with constants
- Don't expose sensitive data in client-side config

**Utils**

- Don't add side effects to utility functions
- Don't make utilities depend on application context
- Don't put business rules in utilities
- Don't create utilities that are only used once

**Helpers**

- Don't create helpers for generic operations
- Don't make helpers too generic (use utils instead)
- Don't ignore the single responsibility principle
- Don't create helpers that are just thin wrappers

### 🎯 Decision Tree: Which File Type Should I Use?

Is it a value?
├─ YES: Does it change based on environment?
│ ├─ YES: Use .config.ts
│ └─ NO: Use .constants.ts
│
└─ NO: It's a function
└─ Is it pure (no side effects, same input = same output)?
├─ YES: Is it generic and reusable anywhere?
│ ├─ YES: Use .util.ts
│ └─ NO: Use .helper.ts (domain-specific)
│
└─ NO: Has side effects or business logic
└─ Use .helper.ts
