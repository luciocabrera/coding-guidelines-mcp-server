## 💻 Code Standard: Top-Level Await Over Promise Chains

### 🎯 Objective

To improve code readability, error handling, and debugging by using top-level `await` instead of promise chains (`.then()`, `.catch()`) in ES modules. Top-level await provides cleaner, more synchronous-looking code and better stack traces while maintaining the same asynchronous behavior.

### 📜 Rule Details

1.  **Use Top-Level Await:** In ES modules (files with `"type": "module"` or `.mjs` extension), use top-level `await` instead of promise chains for module initialization code.

2.  **Replace `.catch()` with `try/catch`:** Convert promise `.catch()` handlers to `try/catch` blocks for more consistent error handling.

3.  **Remove `.then()` Chains:** Replace `.then()` chains with sequential `await` statements.

4.  **ES Module Requirement:** Top-level await is only available in ES modules. Ensure your `package.json` has `"type": "module"` or use `.mjs` files.

5.  **Main Function Pattern:** Instead of defining `main()` and calling it with `.catch()`, write the code directly at the top level with `try/catch`.

### 🔍 Why Top-Level Await is Better

Top-level await provides several advantages:

- **Better readability**: Code reads sequentially, like synchronous code
- **Improved error handling**: Standard `try/catch` blocks instead of callback-based error handling
- **Better stack traces**: Errors show the actual line where they occurred
- **Simpler debugging**: Can use debugger breakpoints more naturally
- **Consistency**: All async code uses the same `async/await` pattern
- **Less boilerplate**: No need to wrap everything in a `main()` function

### ✅ Required Code Snippets (The "Do")

#### 1\. Module Initialization with Top-Level Await

Use top-level await for module setup code instead of promise chains.

```typescript
// ✅ DO: Use top-level await for module initialization
// File: server.ts

import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';

const server = new Server(
  {
    name: 'my-server',
    version: '1.0.0',
  },
  {
    capabilities: {
      resources: {},
    },
  },
);

// Top-level await - clean and straightforward
try {
  const transport = new StdioServerTransport();
  await server.connect(transport);
  console.error('Server running on stdio');
} catch (error: unknown) {
  console.error('Fatal error starting server:', error);
  process.exit(1);
}
```

#### 2\. Database Connection

Use top-level await for database initialization.

```typescript
// ✅ DO: Top-level await for database connection
// File: database.ts

import { createConnection } from './db-client.js';

type DatabaseConfig = {
  host: string;
  port: number;
  database: string;
};

const config: DatabaseConfig = {
  host: process.env.DB_HOST ?? 'localhost',
  port: Number.parseInt(process.env.DB_PORT ?? '5432', 10),
  database: process.env.DB_NAME ?? 'myapp',
};

let connection;

try {
  connection = await createConnection(config);
  console.log('Database connected successfully');
} catch (error: unknown) {
  console.error('Database connection failed:', error);
  process.exit(1);
}

export { connection };
```

#### 3\. Configuration Loading

Load configuration files using top-level await.

```typescript
// ✅ DO: Load config with top-level await
// File: config.ts

import { readFile } from 'node:fs/promises';

type AppConfig = {
  apiUrl: string;
  apiKey: string;
  timeout: number;
};

let config: AppConfig;

try {
  const configData = await readFile('./config.json', 'utf8');
  config = JSON.parse(configData) as AppConfig;
} catch (error: unknown) {
  console.error('Failed to load config:', error);
  // Use default config
  config = {
    apiKey: '',
    apiUrl: 'https://api.example.com',
    timeout: 5000,
  };
}

export { config };
```

#### 4\. Sequential Async Operations

Use multiple await statements for sequential operations.

```typescript
// ✅ DO: Sequential awaits at top level
// File: initialize-app.ts

import { initDatabase } from './database.js';
import { loadPlugins } from './plugins.js';
import { startServer } from './server.js';

try {
  console.log('Initializing database...');
  await initDatabase();

  console.log('Loading plugins...');
  await loadPlugins();

  console.log('Starting server...');
  await startServer();

  console.log('Application started successfully');
} catch (error: unknown) {
  console.error('Application startup failed:', error);
  process.exit(1);
}
```

#### 5\. Parallel Async Operations

Use `Promise.all()` with top-level await for parallel operations.

```typescript
// ✅ DO: Parallel operations with Promise.all
// File: load-resources.ts

import { loadConfig } from './config.js';
import { loadTranslations } from './i18n.js';
import { loadTemplates } from './templates.js';

try {
  // Load all resources in parallel
  const [config, translations, templates] = await Promise.all([
    loadConfig(),
    loadTranslations(),
    loadTemplates(),
  ]);

  console.log('All resources loaded successfully');
  export { config, templates, translations };
} catch (error: unknown) {
  console.error('Failed to load resources:', error);
  process.exit(1);
}
```

### ❌ Forbidden Code Snippets (The "Don't")

#### 1\. Don't Use Promise Chains with .then()/.catch()

```typescript
// ❌ DON'T: Use promise chains
// File: bad-server.ts

import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';

const server = new Server({ name: 'my-server', version: '1.0.0' }, {});

// WRONG: Using .then()/.catch() instead of top-level await
server
  .connect(new StdioServerTransport())
  .then(() => {
    console.error('Server running');
  })
  .catch((error) => {
    console.error('Error:', error);
    process.exit(1);
  });
```

#### 2\. Don't Wrap in Main Function with .catch()

```typescript
// ❌ DON'T: Wrap in main() function with .catch()
// File: bad-main.ts

import { startApp } from './app.js';

async function main() {
  await startApp();
  console.log('App started');
}

// WRONG: Using .catch() on main function
main().catch((error) => {
  console.error('Fatal error:', error);
  process.exit(1);
});
```

#### 3\. Don't Mix Promise Chains with Async/Await

```typescript
// ❌ DON'T: Mix promise chains and await
// File: bad-mixed.ts

import { fetchData } from './api.js';

// WRONG: Mixing patterns
fetchData()
  .then(async (data) => {
    await processData(data);
    return data;
  })
  .catch((error) => {
    console.error(error);
  });
```

#### 4\. Don't Use Nested .then() Chains

```typescript
// ❌ DON'T: Nest .then() calls
// File: bad-nested.ts

import { loadConfig } from './config.js';
import { initDatabase } from './database.js';

// WRONG: Nested promise chains
loadConfig()
  .then((config) => {
    return initDatabase(config).then((db) => {
      return { config, db };
    });
  })
  .catch((error) => {
    console.error(error);
  });
```

- [ ] Error handling uses `try/catch` with `: unknown` type on error
- [ ] Sequential operations use multiple `await` statements
- [ ] Parallel operations use `Promise.all()` with `await`

### 🎯 Summary

**Use top-level `await` instead of promise chains** in ES modules. This provides cleaner, more readable code with better error handling and debugging. Replace `.then()/.catch()` chains with sequential `await` statements wrapped in `try/catch` blocks. Eliminate the `main()` function pattern in favor of direct top-level async code.

### 🔄 Migration Pattern

To convert existing code:

1. **Remove the main function wrapper**:

   ```typescript
   // Before
   async function main() {
     await doWork();
   }
   main().catch((error) => console.error(error));

   // After
   try {
     await doWork();
   } catch (error: unknown) {
     console.error(error);
   }
   ```

2. **Convert .then() chains to await**:

   ```typescript
   // Before
   fetchData()
     .then((data) => processData(data))
     .then((result) => saveResult(result));

   // After
   const data = await fetchData();
   const result = await processData(data);
   await saveResult(result);
   ```

3. **Convert .catch() to try/catch**:

   ```typescript
   // Before
   somePromise().catch((error) => handleError(error));

   // After
   try {
     await somePromise();
   } catch (error: unknown) {
     handleError(error);
   }
   ```
