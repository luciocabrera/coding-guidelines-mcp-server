## 💻 Code Standard: Safe Object Property Access

### 🎯 Objective

To prevent object injection vulnerabilities by ensuring safe access to object properties using dynamic keys. When accessing object properties with variables (bracket notation), there's a risk of prototype pollution and accessing unintended properties. This standard requires validation of keys before use and safe patterns for dynamic property access to prevent security vulnerabilities.

### 📜 Rule Details

1.  **Validate Dynamic Keys:** Always validate that dynamic keys exist in the object before accessing properties with bracket notation.

2.  **Use Type Guards:** When accessing properties dynamically, use type guards or `hasOwnProperty` checks to ensure the key is safe.

3.  **Avoid Prototype Chain:** Use `Object.hasOwn()` or `Object.prototype.hasOwnProperty.call()` to check only own properties, not inherited ones.

4.  **Whitelist Keys:** For known sets of keys, validate against a whitelist before accessing properties.

5.  **Use Maps for Dynamic Keys:** When dealing with truly dynamic keys, consider using `Map` instead of plain objects.

### 🔍 What is Object Injection?

Object injection occurs when:

- Using user input or external data as object keys without validation
- Accessing object properties with bracket notation using untrusted keys
- Potential access to prototype chain properties (`__proto__`, `constructor`, etc.)
- Risk of prototype pollution attacks

### ✅ Required Code Snippets (The "Do")

#### 1\. Validate Keys Before Access

Always check that keys exist before using them to access properties.

```typescript
// ✅ DO: Validate keys before dynamic property access
// File: get-config-value.util.ts

type Config = {
  apiUrl: string;
  timeout: number;
  retries: number;
};

type GetConfigValueArgs = {
  config: Config;
  key: string;
};

export const getConfigValue = ({ config, key }: GetConfigValueArgs): unknown => {
  // Validate key exists before access
  if (!Object.hasOwn(config, key)) {
    throw new Error(`Invalid config key: ${key}`);
  }

  // Type-safe access after validation
  return config[key as keyof Config];
};
```

```typescript
// ✅ DO: Use type guards for safe property access
// File: get-property.util.ts

const isValidKey = <T extends object>(obj: T, key: string | number | symbol): key is keyof T => {
  return Object.hasOwn(obj, key);
};

type GetPropertyArgs<T extends object> = {
  obj: T;
  key: string;
};

export const getProperty = <T extends object>({
  obj,
  key,
}: GetPropertyArgs<T>): T[keyof T] | undefined => {
  if (!isValidKey(obj, key)) {
    return undefined;
  }

  return obj[key];
};
```

#### 2\. Whitelist Known Keys

For objects with known keys, validate against a whitelist.

```typescript
// ✅ DO: Use whitelist for known keys
// File: process-settings.util.ts

type Settings = {
  theme: string;
  language: string;
  timezone: string;
};

const VALID_SETTING_KEYS: ReadonlyArray<keyof Settings> = ['theme', 'language', 'timezone'];

type GetSettingArgs = {
  settings: Settings;
  key: string;
};

export const getSetting = ({ settings, key }: GetSettingArgs): string => {
  // Check against whitelist
  if (!VALID_SETTING_KEYS.includes(key as keyof Settings)) {
    throw new Error(`Invalid setting key: ${key}`);
  }

  return settings[key as keyof Settings];
};
```

```typescript
// ✅ DO: Use const assertion for key validation
// File: get-translation.util.ts

const TRANSLATION_KEYS = ['welcome', 'goodbye', 'error', 'success'] as const;
type TranslationKey = (typeof TRANSLATION_KEYS)[number];

type Translations = Record<TranslationKey, string>;

type GetTranslationArgs = {
  translations: Translations;
  key: string;
};

const isTranslationKey = (key: string): key is TranslationKey => {
  return TRANSLATION_KEYS.includes(key as TranslationKey);
};

export const getTranslation = ({ translations, key }: GetTranslationArgs): string => {
  if (!isTranslationKey(key)) {
    return 'Translation not found';
  }

  return translations[key];
};
```

#### 3\. Use Maps for Dynamic Keys

When keys are truly dynamic, use `Map` instead of objects.

```typescript
// ✅ DO: Use Map for dynamic keys
// File: cache.util.ts

type CacheValue = {
  data: unknown;
  timestamp: number;
};

export class Cache {
  private readonly store = new Map<string, CacheValue>();

  public set(key: string, data: unknown): void {
    this.store.set(key, {
      data,
      timestamp: Date.now(),
    });
  }

  public get(key: string): unknown | undefined {
    const value = this.store.get(key);
    return value?.data;
  }

  public has(key: string): boolean {
    return this.store.has(key);
  }

  public delete(key: string): boolean {
    return this.store.delete(key);
  }
}
```

```typescript
// ✅ DO: Use Map for user-controlled keys
// File: user-preferences.util.ts

type PreferenceValue = string | number | boolean;

export class UserPreferences {
  private readonly preferences = new Map<string, PreferenceValue>();

  public setPreference(key: string, value: PreferenceValue): void {
    // No object injection risk with Map
    this.preferences.set(key, value);
  }

  public getPreference(key: string): PreferenceValue | undefined {
    return this.preferences.get(key);
  }
}
```

#### 4\. Safe Record Access with Type Safety

Use typed records with proper validation.

```typescript
// ✅ DO: Use typed records with validation
// File: get-status-message.util.ts

type StatusCode = 200 | 404 | 500;

const STATUS_MESSAGES: Record<StatusCode, string> = {
  200: 'Success',
  404: 'Not Found',
  500: 'Server Error',
};

type GetStatusMessageArgs = {
  code: number;
};

const isStatusCode = (code: number): code is StatusCode => {
  return code === 200 || code === 404 || code === 500;
};

export const getStatusMessage = ({ code }: GetStatusMessageArgs): string => {
  if (!isStatusCode(code)) {
    return 'Unknown Status';
  }

  return STATUS_MESSAGES[code];
};
```

#### 5\. Avoid Prototype Pollution

Always use own property checks, not `in` operator.

```typescript
// ✅ DO: Use Object.hasOwn to avoid prototype chain
// File: merge-options.util.ts

type Options = {
  [key: string]: unknown;
};

type MergeOptionsArgs = {
  defaults: Options;
  overrides: Options;
};

export const mergeOptions = ({ defaults, overrides }: MergeOptionsArgs): Options => {
  const result: Options = { ...defaults };

  for (const key of Object.keys(overrides)) {
    // Use Object.hasOwn to check only own properties
    if (Object.hasOwn(overrides, key)) {
      result[key] = overrides[key];
    }
  }

  return result;
};
```

### ❌ Anti-Patterns (The "Don't")

#### 1\. Direct Bracket Notation Without Validation

```typescript
// ❌ DON'T: Use bracket notation without validation
// File: get-value.util.ts (WRONG)

type Config = {
  apiKey: string;
  timeout: number;
};

type GetValueArgs = {
  config: Config;
  key: string;
};

export const getValue = ({ config, key }: GetValueArgs) => {
  // ❌ WRONG: Object injection vulnerability
  return config[key];
};

// Dangerous: getValue({ config, key: '__proto__' }) could access prototype
```

**Why it's wrong:**

- No validation of the key before access
- Could access prototype chain properties
- Security vulnerability for user-controlled keys

**How to fix:**

```typescript
// ✅ CORRECT: Validate before access
export const getValue = ({ config, key }: GetValueArgs): unknown => {
  if (!Object.hasOwn(config, key)) {
    throw new Error(`Invalid key: ${key}`);
  }
  return config[key as keyof Config];
};
```

#### 2\. Using `in` Operator for Validation

```typescript
// ❌ DON'T: Use 'in' operator (checks prototype chain)
// File: has-property.util.ts (WRONG)

type HasPropertyArgs = {
  obj: Record<string, unknown>;
  key: string;
};

export const hasProperty = ({ obj, key }: HasPropertyArgs): boolean => {
  // ❌ WRONG: 'in' checks prototype chain
  return key in obj;
};

// Dangerous: hasProperty({ obj: {}, key: 'toString' }) returns true
```

**Why it's wrong:**

- `in` operator checks the entire prototype chain
- Returns true for inherited properties
- Not safe for validation

**How to fix:**

```typescript
// ✅ CORRECT: Use Object.hasOwn
export const hasProperty = ({ obj, key }: HasPropertyArgs): boolean => {
  return Object.hasOwn(obj, key);
};
```

#### 3\. Array Access with Untrusted Indices

```typescript
// ❌ DON'T: Access arrays with untrusted indices
// File: get-item.util.ts (WRONG)

type GetItemArgs = {
  items: string[];
  index: string;
};

export const getItem = ({ items, index }: GetItemArgs) => {
  // ❌ WRONG: Could access Array prototype properties
  return items[index];
};

// Dangerous: getItem({ items: [], index: 'constructor' })
```

**Why it's wrong:**

- String index on array can access prototype
- No bounds checking
- Security risk

**How to fix:**

```typescript
// ✅ CORRECT: Validate index is a number and in bounds
export const getItem = ({ items, index }: GetItemArgs): string | undefined => {
  const numIndex = Number.parseInt(index, 10);

  if (Number.isNaN(numIndex) || numIndex < 0 || numIndex >= items.length) {
    return undefined;
  }

  return items[numIndex];
};
```

#### 4\. Building Objects from User Input

```typescript
// ❌ DON'T: Build objects from unchecked user input
// File: create-config.util.ts (WRONG)

type CreateConfigArgs = {
  entries: Array<[string, unknown]>;
};

export const createConfig = ({ entries }: CreateConfigArgs) => {
  const config: Record<string, unknown> = {};

  for (const [key, value] of entries) {
    // ❌ WRONG: Could set __proto__ or constructor
    config[key] = value;
  }

  return config;
};

// Dangerous: createConfig({ entries: [['__proto__', { polluted: true }]] })
```

**Why it's wrong:**

- Allows setting any property including prototype
- Prototype pollution vulnerability
- No key validation

**How to fix:**

```typescript
// ✅ CORRECT: Use Map or validate keys
export const createConfig = ({ entries }: CreateConfigArgs): Map<string, unknown> => {
  const config = new Map<string, unknown>();

  for (const [key, value] of entries) {
    // Safe with Map - no prototype pollution
    config.set(key, value);
  }

  return config;
};
```

#### 5\. Accessing Nested Properties Dynamically

```typescript
// ❌ DON'T: Access nested properties without validation
// File: get-nested.util.ts (WRONG)

type GetNestedArgs = {
  obj: Record<string, unknown>;
  path: string[];
};

export const getNested = ({ obj, path }: GetNestedArgs): unknown => {
  let current: unknown = obj;

  for (const key of path) {
    // ❌ WRONG: No validation at each level
    current = (current as Record<string, unknown>)[key];
  }

  return current;
};
```

**Why it's wrong:**

- No validation at any level
- Could traverse prototype chain
- Type safety lost

**How to fix:**

```typescript
// ✅ CORRECT: Validate at each level
export const getNested = ({ obj, path }: GetNestedArgs): unknown => {
  let current: unknown = obj;

  for (const key of path) {
    if (typeof current !== 'object' || current === null) {
      return undefined;
    }

    if (!Object.hasOwn(current, key)) {
      return undefined;
    }

    current = (current as Record<string, unknown>)[key];
  }

  return current;
};
```

### 📋 Safe Property Access Checklist

- ✅ Use `Object.hasOwn()` to check for own properties
- ✅ Validate keys against whitelists when possible
- ✅ Use type guards for dynamic property access
- ✅ Consider `Map` for truly dynamic keys
- ✅ Never trust user input as object keys without validation
- ❌ Never use `in` operator for security-critical validation
- ❌ Never access properties with bracket notation without checks
- ❌ Never allow `__proto__`, `constructor`, or `prototype` as keys

### 🎯 Summary

- **Always** validate dynamic keys before accessing object properties
- **Always** use `Object.hasOwn()` instead of `in` operator for validation
- **Always** use whitelists for known key sets
- **Always** consider using `Map` for user-controlled keys
- **Never** trust external data as object keys without validation
- **Never** allow access to prototype chain properties
- **Remember** Object injection can lead to prototype pollution
- **Remember** `Map` is immune to prototype pollution
