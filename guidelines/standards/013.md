## 💻 Code Standard: Unknown Type for Catch Clause Variables

### 🎯 Objective

To ensure type-safe error handling by explicitly typing catch clause variables as `unknown` instead of relying on the implicit `any` type. This prevents unsafe operations on error objects and forces proper type narrowing before accessing error properties, leading to more robust error handling code.

### 📜 Rule Details

1.  **Always Type Catch Variables:** Explicitly type catch clause variables as `: unknown`.

2.  **Narrow Before Access:** Use type guards to narrow the error type before accessing properties like `.message` or `.stack`.

3.  **Never Use `any`:** Do not type catch variables as `: any` - this defeats type safety.

4.  **Handle All Error Types:** Remember that thrown values can be anything (strings, numbers, objects, null, etc.), not just `Error` instances.

5.  **Provide Safe Fallbacks:** When extracting error messages, always provide fallback values for non-Error types.

### 🔍 Why Unknown is Safer Than Any

The `unknown` type is safer because:

- **Forces type checking**: You cannot access properties on `unknown` without narrowing the type first
- **Prevents assumptions**: You cannot assume the error is an `Error` instance
- **Catches bugs early**: TypeScript will flag unsafe error property access at compile time
- **Documents intent**: Explicitly shows that the error type is uncertain
- **Matches runtime reality**: JavaScript allows throwing any value, not just Error objects

Using `: unknown` makes error handling code more defensive and robust.

### ✅ Required Code Snippets (The "Do")

#### 1\. Basic Catch with Type Narrowing

Always type catch variables as `unknown` and narrow before use.

```typescript
// ✅ DO: Type catch variable as unknown and narrow
// File: fetch-user.ts

type User = {
  id: string;
  name: string;
};

type FetchUserArgs = {
  userId: string;
};

export const fetchUser = async ({ userId }: FetchUserArgs): Promise<User | undefined> => {
  try {
    const response = await fetch(`/api/users/${userId}`);
    const data = (await response.json()) as User;
    return data;
  } catch (error: unknown) {
    // Type guard to check if error is an Error instance
    if (error instanceof Error) {
      console.error('Failed to fetch user:', error.message);
    } else {
      console.error('Failed to fetch user:', String(error));
    }
    return undefined;
  }
};
```

#### 2\. Extract Error Message Safely

Create a utility function to safely extract error messages.

```typescript
// ✅ DO: Create a safe error message extractor
// File: error-utils.ts

type GetErrorMessageArgs = {
  error: unknown;
};

export const getErrorMessage = ({ error }: GetErrorMessageArgs): string => {
  if (error instanceof Error) {
    return error.message;
  }

  if (typeof error === 'string') {
    return error;
  }

  if (typeof error === 'object' && error !== null && 'message' in error) {
    return String(error.message);
  }

  return 'An unknown error occurred';
};
```

```typescript
// ✅ DO: Use the utility in catch blocks
// File: save-data.ts

type SaveDataArgs = {
  data: Record<string, unknown>;
};

export const saveData = async ({ data }: SaveDataArgs): Promise<boolean> => {
  try {
    await fetch('/api/save', {
      method: 'POST',
      body: JSON.stringify(data),
    });
    return true;
  } catch (error: unknown) {
    const message = getErrorMessage({ error });
    console.error('Save failed:', message);
    return false;
  }
};
```

#### 3\. Handle Different Error Types

Account for the fact that any value can be thrown.

```typescript
// ✅ DO: Handle various thrown types
// File: parse-config.ts

type Config = {
  apiUrl: string;
  timeout: number;
};

type ParseConfigArgs = {
  configString: string;
};

export const parseConfig = ({ configString }: ParseConfigArgs): Config | undefined => {
  try {
    const parsed = JSON.parse(configString) as Config;
    return parsed;
  } catch (error: unknown) {
    // Handle Error instances
    if (error instanceof Error) {
      console.error('JSON parse error:', error.message);
      return undefined;
    }

    // Handle DOMException (in browser environments)
    if (error instanceof DOMException) {
      console.error('DOM error:', error.message);
      return undefined;
    }

    // Handle unknown types
    console.error('Unknown parse error:', String(error));
    return undefined;
  }
};
```

#### 4\. Promise Catch Callbacks

When using `.catch()`, type the parameter as `unknown`.

```typescript
// ✅ DO: Type catch callback parameter as unknown
// File: load-resource.ts

type LoadResourceArgs = {
  resourceId: string;
};

export const loadResource = ({ resourceId }: LoadResourceArgs): void => {
  fetch(`/api/resource/${resourceId}`)
    .then((response) => response.json())
    .then((data) => {
      console.log('Resource loaded:', data);
    })
    .catch((error: unknown) => {
      const message = getErrorMessage({ error });
      console.error('Load failed:', message);
    });
};
```

#### 5\. Re-throwing After Logging

When re-throwing, preserve the original error.

```typescript
// ✅ DO: Re-throw original error after logging
// File: process-transaction.ts

type ProcessTransactionArgs = {
  transactionId: string;
  amount: number;
};

export const processTransaction = async ({
  transactionId,
  amount,
}: ProcessTransactionArgs): Promise<void> => {
  try {
    await fetch('/api/transaction', {
      method: 'POST',
      body: JSON.stringify({ transactionId, amount }),
    });
  } catch (error: unknown) {
    // Log for monitoring
    const message = getErrorMessage({ error });
    console.error(`Transaction ${transactionId} failed:`, message);

    // Re-throw to let caller handle
    throw error;
  }
};
```

### ❌ Forbidden Code Snippets (The "Don't")

#### 1\. Don't Use Implicit Any

```typescript
// ❌ DON'T: Rely on implicit any type
// File: bad-fetch.ts

export const fetchData = async () => {
  try {
    const response = await fetch('/api/data');
    return await response.json();
  } catch (error) {
    // WRONG: error is implicitly any
    console.error('Error:', error.message); // Unsafe property access
  }
};
```

#### 2\. Don't Explicitly Type as Any

```typescript
// ❌ DON'T: Explicitly use any type
// File: bad-error-handler.ts

export const handleOperation = () => {
  try {
    // Some operation
  } catch (error: any) {
    // WRONG: Using any defeats the purpose
    console.error(error.message); // Unsafe
  }
};
```

#### 3\. Don't Access Properties Without Type Guards

```typescript
// ❌ DON'T: Access properties without narrowing
// File: bad-parser.ts

export const parseData = (input: string) => {
  try {
    return JSON.parse(input);
  } catch (error: unknown) {
    // WRONG: Accessing .message without checking if error is an Error
    console.error(error.message); // Type error!
  }
};
```

#### 4\. Don't Assume Error Type

```typescript
// ❌ DON'T: Assume thrown value is always Error
// File: bad-validator.ts

export const validateInput = (input: string): boolean => {
  try {
    if (input.length === 0) {
      throw 'Input is empty'; // String, not Error!
    }
    return true;
  } catch (error: unknown) {
    // WRONG: Assuming error is always Error instance
    console.error((error as Error).message); // Unsafe cast
    return false;
  }
};
```

- [ ] All `.catch()` callback parameters explicitly typed as `: unknown`
- [ ] Type guards used before accessing error properties
- [ ] Error message extraction uses safe utility function or type narrowing
- [ ] Code handles non-Error thrown values gracefully
- [ ] No use of `any` type for error variables
- [ ] No unsafe type assertions on error objects
- [ ] Console logging safely converts unknown errors to strings

### 🎯 Summary

**Always type catch variables as `: unknown`, never `any`.** This forces you to properly narrow the error type before accessing properties, leading to safer error handling code. Use type guards like `instanceof Error` to check error types, and create utility functions to safely extract error messages. Remember that JavaScript allows throwing any value, so defensive error handling is essential.
