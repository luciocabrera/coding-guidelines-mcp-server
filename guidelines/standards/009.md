## 💻 Code Standard: Nullish Coalescing Over Logical OR

### 🎯 Objective

To ensure safer default value handling by using the nullish coalescing operator (`??`) instead of the logical OR operator (`||`) when providing fallback values. The nullish coalescing operator only considers `null` and `undefined` as nullish, while logical OR treats all falsy values (`0`, `''`, `false`, `NaN`, `null`, `undefined`) as triggering the fallback. This prevents subtle bugs where valid falsy values are incorrectly replaced with defaults.

### 📜 Rule Details

1.  **Use `??` for Defaults:** When providing default values for potentially `null` or `undefined` variables, use the nullish coalescing operator (`??`) instead of logical OR (`||`).

2.  **Preserve Falsy Values:** Use `??` to preserve intentional falsy values like `0`, `''`, `false` that should not trigger fallbacks.

3.  **Use `||` for Boolean Logic:** Only use logical OR (`||`) when you specifically want to treat all falsy values as triggering the fallback (rare cases).

4.  **Configuration Values:** When reading environment variables or configuration that might be empty strings or zero, use `??` to avoid incorrect defaults.

5.  **Optional Parameters:** When destructuring optional parameters with default values, prefer `??` to handle `undefined` correctly.

### 🔍 Why Nullish Coalescing is Safer

The key difference:

- **Logical OR (`||`)**: Returns right side if left is `false`, `0`, `''`, `null`, `undefined`, `NaN`
- **Nullish Coalescing (`??`)**: Returns right side ONLY if left is `null` or `undefined`

This matters when:

- `0` is a valid value (counts, indices, percentages)
- `''` is a valid value (empty strings that differ from missing values)
- `false` is a valid value (boolean flags)

### ✅ Required Code Snippets (The "Do")

#### 1\. Environment Variables and Configuration

Use `??` when reading configuration to preserve empty strings and zero values.

```typescript
// ✅ DO: Use ?? for environment variables
// File: config.ts

export const config = {
  port: process.env.PORT ?? '3000', // Preserves PORT if it's set to empty string
  apiKey: process.env.API_KEY ?? 'default-key',
  maxRetries: Number.parseInt(process.env.MAX_RETRIES ?? '3', 10),

  features: {
    isAnalyticsEnabled: process.env.ANALYTICS_ENABLED ?? 'true',
    isDarkMode: process.env.DARK_MODE ?? 'false',
  },
};
```

```typescript
// ✅ DO: Use ?? for application settings
// File: app-settings.ts

type AppSettings = {
  timeout?: number;
  retryCount?: number;
  debugMode?: boolean;
  apiUrl?: string;
};

type GetSettingsArgs = {
  userSettings?: AppSettings;
};

export const getSettings = ({ userSettings }: GetSettingsArgs): Required<AppSettings> => {
  return {
    timeout: userSettings?.timeout ?? 5000, // 0 is valid timeout
    retryCount: userSettings?.retryCount ?? 3, // 0 means no retries
    debugMode: userSettings?.debugMode ?? false, // false is valid, different from missing
    apiUrl: userSettings?.apiUrl ?? 'https://api.example.com',
  };
};
```

#### 2\. Function Parameters with Defaults

Use `??` in destructuring to handle `undefined` correctly.

```typescript
// ✅ DO: Use ?? for optional parameters
// File: paginate.util.ts

type PaginateArgs = {
  page?: number;
  pageSize?: number;
  offset?: number;
};

export const paginate = ({ page, pageSize, offset }: PaginateArgs) => {
  // Use ?? to allow page 0, pageSize 0, offset 0
  const currentPage = page ?? 1;
  const itemsPerPage = pageSize ?? 10;
  const startOffset = offset ?? 0;

  return {
    skip: startOffset + (currentPage - 1) * itemsPerPage,
    take: itemsPerPage,
  };
};
```

```typescript
// ✅ DO: Use ?? for number parameters
// File: calculate-discount.util.ts

type CalculateDiscountArgs = {
  price: number;
  discountPercent?: number;
  minDiscount?: number;
};

export const calculateDiscount = ({
  price,
  discountPercent,
  minDiscount,
}: CalculateDiscountArgs): number => {
  // Use ?? to allow 0% discount or 0 minimum
  const discount = discountPercent ?? 0;
  const minimum = minDiscount ?? 0;

  const calculatedDiscount = (price * discount) / 100;
  return Math.max(calculatedDiscount, minimum);
};
```

#### 3\. Array and String Operations

Use `??` to preserve empty strings and empty arrays as valid values.

```typescript
// ✅ DO: Use ?? for string defaults
// File: format-name.util.ts

type FormatNameArgs = {
  firstName?: string;
  lastName?: string;
  middleName?: string;
};

export const formatName = ({ firstName, lastName, middleName }: FormatNameArgs): string => {
  // Use ?? to allow empty strings, which differ from undefined
  const first = firstName ?? 'Unknown';
  const middle = middleName ?? ''; // Empty string is valid
  const last = lastName ?? '';

  return `${first} ${middle} ${last}`.trim();
};
```

```typescript
// ✅ DO: Use ?? for array defaults
// File: process-items.util.ts

type ProcessItemsArgs = {
  items?: string[];
  filters?: string[];
};

export const processItems = ({ items, filters }: ProcessItemsArgs): string[] => {
  // Use ?? to distinguish between empty array [] and undefined
  const itemList = items ?? [];
  const filterList = filters ?? [];

  return itemList.filter((item) => (filterList.length === 0 ? true : filterList.includes(item)));
};
```

#### 4\. Object Property Access

Use `??` when accessing object properties that might be falsy.

```typescript

type UserProfile = {
```

### ❌ Anti-Patterns (The "Don't")

#### 1\. Using `||` for Numeric Defaults

```typescript
// ❌ DON'T: Use || for numbers (0 is falsy!)
// File: pagination.util.ts (WRONG)

type PaginateArgs = {
  page?: number;
  pageSize?: number;
};

export const paginate = ({ page, pageSize }: PaginateArgs) => {
  // ❌ WRONG: page=0 will be replaced with 1 (bug!)
  const currentPage = page || 1;
  // ❌ WRONG: pageSize=0 will be replaced with 10 (bug!)
  const itemsPerPage = pageSize || 10;

  return {
    skip: (currentPage - 1) * itemsPerPage,
    take: itemsPerPage,
  };
};

// Bug: paginate({ page: 0, pageSize: 0 }) returns skip: -10, take: 10
// Expected: skip: 0, take: 0
```

**Why it's wrong:**

- `0` is a valid page number and page size
- Using `||` treats `0` as falsy and incorrectly applies defaults
- Creates subtle bugs that are hard to detect

**How to fix:**

```typescript
// ✅ CORRECT: Use ?? to preserve 0
export const paginate = ({ page, pageSize }: PaginateArgs) => {
  const currentPage = page ?? 1;
  const itemsPerPage = pageSize ?? 10;

  return {
    skip: (currentPage - 1) * itemsPerPage,
    take: itemsPerPage,
  };
};
```

#### 2\. Using `||` for String Defaults

```typescript
// ❌ DON'T: Use || for strings (empty string is falsy!)
// File: user-input.util.ts (WRONG)

type ProcessInputArgs = {
  searchQuery?: string;
  username?: string;
};

export const processInput = ({ searchQuery, username }: ProcessInputArgs) => {
  // ❌ WRONG: searchQuery='' will be replaced with 'default' (bug!)
  const query = searchQuery || 'default';
  // ❌ WRONG: username='' will be replaced with 'guest' (bug!)
  const user = username || 'guest';

  return { query, user };
};

// Bug: processInput({ searchQuery: '', username: '' }) returns { query: 'default', user: 'guest' }
// Expected: { query: '', user: '' }
```

**Why it's wrong:**

- Empty string `''` is a valid value, different from `undefined`
- User might intentionally clear a field
- Using `||` treats empty string as missing value

**How to fix:**

```typescript
// ✅ CORRECT: Use ?? to preserve empty strings
export const processInput = ({ searchQuery, username }: ProcessInputArgs) => {
  const query = searchQuery ?? 'default';
  const user = username ?? 'guest';

  return { query, user };
};
```

#### 3\. Using `||` for Boolean Defaults

```typescript
// ❌ DON'T: Use || for booleans (false is falsy!)
// File: feature-flags.util.ts (WRONG)

type FeatureFlags = {
  isEnabled?: boolean;
  isVisible?: boolean;
  canEdit?: boolean;
};

type GetFlagsArgs = {
  flags?: FeatureFlags;
};

export const getFlags = ({ flags }: GetFlagsArgs) => {
  // ❌ WRONG: isEnabled=false will be replaced with true (bug!)
  const enabled = flags?.isEnabled || true;
  // ❌ WRONG: isVisible=false will be replaced with true (bug!)
  const visible = flags?.isVisible || true;
  // ❌ WRONG: canEdit=false will be replaced with false, but unclear
  const editable = flags?.canEdit || false;

  return { enabled, visible, editable };
};

// Bug: getFlags({ flags: { isEnabled: false } }) returns { enabled: true, ... }
// Expected: { enabled: false, ... }
```

**Why it's wrong:**

- `false` is a valid boolean value, different from `undefined`
- Using `||` with booleans is extremely error-prone
- Inverts the intended logic

**How to fix:**

```typescript
// ✅ CORRECT: Use ?? for booleans
export const getFlags = ({ flags }: GetFlagsArgs) => {
  const enabled = flags?.isEnabled ?? true;
  const visible = flags?.isVisible ?? true;
  const editable = flags?.canEdit ?? false;

  return { enabled, visible, editable };
};
```

#### 4\. Using `||` for Configuration

```typescript
// ❌ DON'T: Use || for environment variables
// File: config.ts (WRONG)

export const config = {
  // ❌ WRONG: If PORT is set to '', falls back to '3000'
  port: process.env.PORT || '3000',

  // ❌ WRONG: If MAX_RETRIES is '0', falls back to '3'
  maxRetries: process.env.MAX_RETRIES || '3',

  // ❌ WRONG: If DEBUG is 'false', treated as falsy
  debug: process.env.DEBUG || 'true',
};
```

**Why it's wrong:**

- Environment variables can be intentionally set to empty strings
- `'0'` and `'false'` are valid string values
- Using `||` prevents proper configuration

**How to fix:**

```typescript
// ✅ CORRECT: Use ?? for configuration
export const config = {
  port: process.env.PORT ?? '3000',
  maxRetries: process.env.MAX_RETRIES ?? '3',
  debug: process.env.DEBUG ?? 'true',
};
```

#### 5\. Using `||` in Chains

```typescript
// ❌ DON'T: Chain || operators with falsy values
// File: user-settings.util.ts (WRONG)

type UserSettings = {
  theme?: string;
  fontSize?: number;
  notifications?: boolean;
};

type ApplySettingsArgs = {
  userSettings?: UserSettings;
  defaultSettings?: UserSettings;
};

export const applySettings = ({ userSettings, defaultSettings }: ApplySettingsArgs) => {
  // ❌ WRONG: Multiple issues with falsy values
  const theme = userSettings?.theme || defaultSettings?.theme || 'light';
  const fontSize = userSettings?.fontSize || defaultSettings?.fontSize || 16;
  const notifications = userSettings?.notifications || defaultSettings?.notifications || true;

  return { theme, fontSize, notifications };
};
```

**Why it's wrong:**

- Empty string themes are treated as missing
- `fontSize: 0` is treated as missing
- `notifications: false` is treated as missing
- Multi-level fallback loses intentional values

**How to fix:**

```typescript
// ✅ CORRECT: Use ?? for proper nullish checks
export const applySettings = ({ userSettings, defaultSettings }: ApplySettingsArgs) => {
  const theme = userSettings?.theme ?? defaultSettings?.theme ?? 'light';
  const fontSize = userSettings?.fontSize ?? defaultSettings?.fontSize ?? 16;
  const notifications = userSettings?.notifications ?? defaultSettings?.notifications ?? true;

  return { theme, fontSize, notifications };
};
```

### 📋 Decision Matrix: `??` vs `||`

| Scenario                      | Use `??` | Use ` |                                          | `   | Reason |
| ----------------------------- | -------- | ----- | ---------------------------------------- | --- | ------ |
| Number defaults (0 is valid)  | ✅       | ❌    | `0` should not trigger fallback          |
| String defaults ('' is valid) | ✅       | ❌    | Empty string should not trigger fallback |
| Boolean defaults              | ✅       | ❌    | `false` should not trigger fallback      |
| Array defaults                | ✅       | ❌    | `[]` should not trigger fallback         |
| Config/env variables          | ✅       | ❌    | Preserve all set values                  |
| Optional parameters           | ✅       | ❌    | Only `undefined` should trigger default  |
| Boolean logic (non-defaults)  | ❌       | ✅    | When you want falsy → true behavior      |

### 🎯 Summary

- **Always** use `??` when providing default values for potentially `null` or `undefined` variables
- **Always** use `??` for numeric, string, and boolean defaults to preserve `0`, `''`, and `false`
- **Always** use `??` for environment variables and configuration settings
- **Always** use `??` for optional function parameters
- **Never** use `||` for default values unless you specifically want to treat all falsy values as triggers
- **Never** assume `||` and `??` are interchangeable - they have different semantics
- **Remember** `??` = "use fallback only if `null` or `undefined`"
- **Remember** `||` = "use fallback if falsy (includes `0`, `''`, `false`, `NaN`)"
