## 💻 Code Standard: Safe File System Operations

### 🎯 Objective

To prevent path traversal vulnerabilities and ensure secure file system operations by validating all file paths before use. When file paths are constructed from variables or user input, there's a risk of accessing files outside the intended directory (path traversal attacks). This standard requires path validation, sanitization, and safe path construction patterns to prevent unauthorized file access.

### 📜 Rule Details

1.  **Validate File Paths:** Always validate that file paths are within expected directories before reading or writing.

2.  **Use Path Resolution:** Use `path.resolve()` and check that resolved paths are within allowed directories.

3.  **Sanitize User Input:** Never use user input directly in file paths without validation and sanitization.

4.  **Whitelist Allowed Paths:** Maintain a whitelist of allowed base directories and validate all paths against it.

5.  **Avoid Dynamic Path Construction:** When possible, use hardcoded paths or validated enums instead of dynamic path construction.

### 🔍 What is Path Traversal?

Path traversal occurs when:

- Using `..` sequences to navigate outside intended directories
- User input is used to construct file paths without validation
- Reading or writing files outside allowed directories
- Accessing sensitive system files (e.g., `/etc/passwd`, `C:\Windows\System32`)

Examples of dangerous paths:

- `../../etc/passwd`
- `..\\..\\Windows\\System32\\config\\sam`
- `/absolute/path/to/sensitive/file`

### ✅ Required Code Snippets (The "Do")

#### 1\. Use Nominal Type Pattern for Maximum Safety (Recommended)

The safest pattern uses a nominal type to ensure paths are validated at compile time.

```typescript
// ✅ DO: Use ValidatedPath nominal type pattern
// File: safe-file-reader.ts

import { readFile } from 'node:fs/promises';
import path from 'node:path';

/**
 * A validated safe file path that has been checked for traversal attacks
 * This nominal type prevents accidental use of unvalidated paths
 */
type ValidatedPath = string & { readonly _validated: unique symbol };

type ValidatePathArgs = {
  basePath: string;
  filePath: string;
};

/**
 * Validates a file path is within the allowed base directory
 * Returns a ValidatedPath that can be safely used with readSafeFile
 */
export const validatePath = ({
  basePath,
  filePath,
}: ValidatePathArgs): ValidatedPath | undefined => {
  const resolvedBase = path.resolve(basePath);
  const resolvedPath = path.resolve(basePath, filePath);

  // Ensure the resolved path is within the base directory
  if (!resolvedPath.startsWith(resolvedBase + path.sep) && resolvedPath !== resolvedBase) {
    return undefined;
  }

  return resolvedPath as ValidatedPath;
};

/**
 * Reads a file that has been validated to be safe
 * Only accepts ValidatedPath to ensure the path has been checked
 *
 * This is the ONLY place where we read files with dynamic paths.
 * The ValidatedPath nominal type ensures all paths have been validated.
 * TypeScript enforces this at compile time - you cannot pass a regular string.
 */
export const readSafeFile = async (validatedPath: ValidatedPath): Promise<string> => {
  // eslint-disable-next-line security/detect-non-literal-fs-filename -- Path is validated via ValidatedPath nominal type
  return await readFile(validatedPath, 'utf8');
};
```

**Why this pattern is superior:**

- ✅ TypeScript prevents passing unvalidated strings to `readSafeFile()`
- ✅ Validation logic centralized in one place
- ✅ Security warning isolated to one controlled location
- ✅ Compile-time guarantee that paths are validated
- ✅ Clear separation between validated and unvalidated paths

#### 2\. Validate Paths Against Base Directory (Alternative)

Always resolve paths and verify they're within allowed directories.

```typescript
// ✅ DO: Validate paths are within base directory
// File: read-safe-file.util.ts

import { readFile } from 'node:fs/promises';
import path from 'node:path';

type ReadSafeFileArgs = {
  baseDir: string;
  filename: string;
};

const isPathSafe = (baseDir: string, filePath: string): boolean => {
  const resolvedBase = path.resolve(baseDir);
  const resolvedPath = path.resolve(baseDir, filePath);

  // Check that resolved path starts with base directory
  return resolvedPath.startsWith(resolvedBase + path.sep) || resolvedPath === resolvedBase;
};

export const readSafeFile = async ({ baseDir, filename }: ReadSafeFileArgs): Promise<string> => {
  if (!isPathSafe(baseDir, filename)) {
    throw new Error(`Path traversal detected: ${filename}`);
  }

  const safePath = path.resolve(baseDir, filename);
  return await readFile(safePath, 'utf8');
};
```

```typescript
// ✅ DO: Create safe path validator utility
// File: validate-path.util.ts

import path from 'node:path';

type ValidatePathArgs = {
  basePath: string;
  userPath: string;
};

export const validatePath = ({ basePath, userPath }: ValidatePathArgs): string => {
  const resolvedBase = path.resolve(basePath);
  const resolvedUser = path.resolve(basePath, userPath);

  // Ensure resolved path is within base directory
  if (!resolvedUser.startsWith(resolvedBase + path.sep) && resolvedUser !== resolvedBase) {
    throw new Error('Invalid path: outside allowed directory');
  }

  // Check for dangerous patterns
  if (userPath.includes('..') || path.isAbsolute(userPath)) {
    throw new Error('Invalid path: contains dangerous patterns');
  }

  return resolvedUser;
};
```

#### 2\. Use Whitelisted Filenames

For known file sets, use whitelists instead of dynamic paths.

```typescript
// ✅ DO: Use whitelist for allowed files
// File: read-config-file.util.ts

import { readFile } from 'node:fs/promises';
import path from 'node:path';

const ALLOWED_CONFIG_FILES = [
  'app.config.json',
  'database.config.json',
  'api.config.json',
] as const;

type ConfigFileName = (typeof ALLOWED_CONFIG_FILES)[number];

const isAllowedConfigFile = (filename: string): filename is ConfigFileName => {
  return ALLOWED_CONFIG_FILES.includes(filename as ConfigFileName);
};

type ReadConfigFileArgs = {
  configDir: string;
  filename: string;
};

export const readConfigFile = async ({
  configDir,
  filename,
}: ReadConfigFileArgs): Promise<string> => {
  if (!isAllowedConfigFile(filename)) {
    throw new Error(`File not in whitelist: ${filename}`);
  }

  const filePath = path.join(configDir, filename);
  return await readFile(filePath, 'utf8');
};
```

#### 3\. Sanitize Filenames

Remove dangerous characters from user-provided filenames.

```typescript
// ✅ DO: Sanitize user-provided filenames
// File: sanitize-filename.util.ts

type SanitizeFilenameArgs = {
  filename: string;
};

export const sanitizeFilename = ({ filename }: SanitizeFilenameArgs): string => {
  // Remove path separators and parent directory references
  let sanitized = filename.replace(/\.\./g, '').replace(/[/\\]/g, '').replace(/^\.+/, '');

  // Allow only alphanumeric, hyphens, underscores, and dots
  sanitized = sanitized.replace(/[^a-zA-Z0-9._-]/g, '_');

  // Prevent hidden files
  if (sanitized.startsWith('.')) {
    sanitized = sanitized.slice(1);
  }

  // Ensure not empty
  if (sanitized.length === 0) {
    throw new Error('Invalid filename');
  }

  return sanitized;
};
```

#### 4\. Use Constant Base Paths

Define allowed directories as constants, not variables.

```typescript
// ✅ DO: Use constant base paths
// File: file-paths.const.ts

import path from 'node:path';

export const FILE_PATHS = {
  UPLOADS: path.resolve(process.cwd(), 'uploads'),
  TEMP: path.resolve(process.cwd(), 'temp'),
  CONFIGS: path.resolve(process.cwd(), 'config'),
  LOGS: path.resolve(process.cwd(), 'logs'),
} as const;
```

```typescript
// ✅ DO: Validate against constant base paths
// File: save-upload.util.ts

import { writeFile } from 'node:fs/promises';
import path from 'node:path';
import { FILE_PATHS } from './file-paths.const';
import { sanitizeFilename } from './sanitize-filename.util';

type SaveUploadArgs = {
  filename: string;
  content: Buffer;
};

export const saveUpload = async ({ filename, content }: SaveUploadArgs): Promise<string> => {
  const sanitized = sanitizeFilename({ filename });
  const fullPath = path.join(FILE_PATHS.UPLOADS, sanitized);

  // Verify still within uploads directory
  if (!fullPath.startsWith(FILE_PATHS.UPLOADS + path.sep)) {
    throw new Error('Path traversal detected');
  }

  await writeFile(fullPath, content);
  return fullPath;
};
```

#### 5\. Log and Monitor File Access

Log file operations for security auditing.

```typescript
// ✅ DO: Log file operations
// File: read-file-safe.util.ts

import { readFile } from 'node:fs/promises';
import path from 'node:path';

type ReadFileSafeArgs = {
  baseDir: string;
  filename: string;
  userId?: string;
};

export const readFileSafe = async ({
  baseDir,
  filename,
  userId,
}: ReadFileSafeArgs): Promise<string> => {
  const resolvedBase = path.resolve(baseDir);
  const resolvedPath = path.resolve(baseDir, filename);

  // Validate path
  if (!resolvedPath.startsWith(resolvedBase + path.sep)) {
    console.error('Path traversal attempt', {
      userId,
      requestedPath: filename,
      baseDir,
    });
    throw new Error('Access denied');
  }

  // Log successful access
  console.info('File accessed', {
    userId,
    path: resolvedPath,
    timestamp: new Date().toISOString(),
  });

  return await readFile(resolvedPath, 'utf8');
};
```

### ❌ Anti-Patterns (The "Don't")

#### 1\. Using Variables Directly in File Paths

```typescript
// ❌ DON'T: Use unvalidated variables in readFile
// File: read-user-file.util.ts (WRONG)

import { readFile } from 'node:fs/promises';
import path from 'node:path';

type ReadUserFileArgs = {
  directory: string;
  filename: string;
};

export const readUserFile = async ({ directory, filename }: ReadUserFileArgs): Promise<string> => {
  // ❌ WRONG: Path traversal vulnerability
  const filePath = path.join(directory, filename);
  return await readFile(filePath, 'utf8');
};

// Dangerous: readUserFile({ directory: '/app/data', filename: '../../etc/passwd' })
```

**Why it's wrong:**

- No validation of path safety
- Allows path traversal with `../`
- Could access any file on the system

**How to fix:**

```typescript
// ✅ CORRECT: Validate path before reading
export const readUserFile = async ({ directory, filename }: ReadUserFileArgs): Promise<string> => {
  const resolvedBase = path.resolve(directory);
  const resolvedPath = path.resolve(directory, filename);

  if (!resolvedPath.startsWith(resolvedBase + path.sep)) {
    throw new Error('Path traversal detected');
  }

  return await readFile(resolvedPath, 'utf8');
};
```

#### 2\. Trusting User Input for Paths

```typescript
// ❌ DON'T: Trust user input directly
// File: delete-file.util.ts (WRONG)

import { unlink } from 'node:fs/promises';

type DeleteFileArgs = {
  filepath: string;
};

export const deleteFile = async ({ filepath }: DeleteFileArgs): Promise<void> => {
  // ❌ WRONG: User controls entire path
  await unlink(filepath);
};

// Dangerous: deleteFile({ filepath: '/etc/passwd' })
```

**Why it's wrong:**

- User controls entire file path
- No restrictions on what can be deleted
- Critical security vulnerability

**How to fix:**

```typescript
// ✅ CORRECT: Restrict to specific directory with validation
const ALLOWED_DELETE_DIR = path.resolve(process.cwd(), 'user-files');

export const deleteFile = async ({ filepath }: DeleteFileArgs): Promise<void> => {
  const resolved = path.resolve(ALLOWED_DELETE_DIR, filepath);

  if (!resolved.startsWith(ALLOWED_DELETE_DIR + path.sep)) {
    throw new Error('Cannot delete files outside user directory');
  }

  await unlink(resolved);
};
```

#### 3\. Building Paths from Multiple Variables

```typescript
// ❌ DON'T: Build paths from multiple unchecked variables
// File: load-resource.util.ts (WRONG)

import { readFile } from 'node:fs/promises';
import path from 'node:path';

type LoadResourceArgs = {
  category: string;
  subcategory: string;
  filename: string;
};

export const loadResource = async ({
  category,
  subcategory,
  filename,
}: LoadResourceArgs): Promise<string> => {
  // ❌ WRONG: All parts are unchecked
  const filePath = path.join('/resources', category, subcategory, filename);
  return await readFile(filePath, 'utf8');
};

// Dangerous: loadResource({ category: '..', subcategory: '..', filename: 'etc/passwd' })
```

**Why it's wrong:**

- Multiple points of injection
- Complex path traversal possibility
- No validation at any level

**How to fix:**

```typescript
// ✅ CORRECT: Whitelist all path components
const ALLOWED_CATEGORIES = ['images', 'documents', 'videos'] as const;
const ALLOWED_SUBCATEGORIES = ['public', 'private'] as const;

export const loadResource = async ({
  category,
  subcategory,
  filename,
}: LoadResourceArgs): Promise<string> => {
  if (!ALLOWED_CATEGORIES.includes(category as any)) {
    throw new Error('Invalid category');
  }

  if (!ALLOWED_SUBCATEGORIES.includes(subcategory as any)) {
    throw new Error('Invalid subcategory');
  }

  const sanitized = sanitizeFilename({ filename });
  const filePath = path.join('/resources', category, subcategory, sanitized);

  return await readFile(filePath, 'utf8');
};
```

#### 4\. Using Absolute Paths from Input

```typescript
// ❌ DON'T: Allow absolute paths from user input
// File: read-log.util.ts (WRONG)

import { readFile } from 'node:fs/promises';

type ReadLogArgs = {
  logPath: string;
};

export const readLog = async ({ logPath }: ReadLogArgs): Promise<string> => {
  // ❌ WRONG: Allows any absolute path
  return await readFile(logPath, 'utf8');
};

// Dangerous: readLog({ logPath: '/etc/shadow' })
```

**Why it's wrong:**

- User can specify any file on system
- No directory restrictions
- Complete file system access

**How to fix:**

```typescript
// ✅ CORRECT: Restrict to logs directory, reject absolute paths
const LOGS_DIR = path.resolve(process.cwd(), 'logs');

export const readLog = async ({ logPath }: ReadLogArgs): Promise<string> => {
  if (path.isAbsolute(logPath)) {
    throw new Error('Absolute paths not allowed');
  }

  const resolved = path.resolve(LOGS_DIR, logPath);

  if (!resolved.startsWith(LOGS_DIR + path.sep)) {
    throw new Error('Path outside logs directory');
  }

  return await readFile(resolved, 'utf8');
};
```

### 📋 Safe File Operations Checklist

- ✅ Validate all paths are within expected directories
- ✅ Use `path.resolve()` to normalize paths
- ✅ Check resolved paths start with allowed base directory
- ✅ Sanitize user-provided filenames
- ✅ Use whitelists for known file sets
- ✅ Reject paths containing `..` or absolute paths
- ✅ Use constant base directories
- ✅ Log file access for security auditing
- ❌ Never use user input directly in file paths
- ❌ Never trust external data for path construction
- ❌ Never allow `..` sequences in paths
- ❌ Never allow absolute paths from user input

### 🎯 Summary

- **Always** validate file paths are within allowed directories
- **Always** use `path.resolve()` and check the result
- **Always** sanitize user-provided filenames
- **Always** use whitelists when possible
- **Never** use user input directly in `readFile`, `writeFile`, etc.
- **Never** trust path construction from external data
- **Remember** Path traversal can expose sensitive files
- **Remember** `../` can escape intended directories
