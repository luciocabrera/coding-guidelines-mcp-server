## 💻 Code Standard: Type-Safe Function Calls and Method Invocations

### 🎯 Objective

To ensure all function calls and method invocations are type-safe by properly typing variables, parameters, and return values. This standard prevents runtime errors caused by calling values of `any` or `unknown` types, improves code reliability, and provides better IDE support through proper type inference. Type-safe calls enable early detection of errors during development rather than in production.

### 📜 Rule Details

1.  **No Unsafe Calls:** Never call a function or method on a value typed as `any` or `unknown` without proper type checking or assertion.
2.  **Explicit Typing:** All variables, parameters, and return values that will be called as functions must have explicit, proper types.
3.  **Type Guards:** When dealing with `unknown` types, use type guards or type assertions to safely narrow the type before calling.
4.  **Error Handling:** When working with external data or APIs, properly type the response and handle potential type mismatches.
5.  **Generic Constraints:** Use generic constraints to ensure type safety when working with generic functions.

### 🔍 What is an Unsafe Call?

An unsafe call occurs when TypeScript cannot verify that a value is actually callable because:

- The value is typed as `any` (disables type checking)
- The value is typed as `unknown` (type must be verified first)
- The value could be `null` or `undefined`
- The type doesn't guarantee the value is a function

#### 4\. Type-Safe API Response Handling

// ✅ DO: Create type-safe API response handlers

type ApiResponse<T> = {
  data: T;
  status: number;
  message: string;
};

type FetchDataArgs<T> = {
  url: string;
  onSuccess: (data: T) => void;
  onError: (error: Error) => void;

  url,
  onSuccess,
  onError,

    if (error instanceof Error) {
      onError(error); // Type-safe: onError expects Error
    } else {
      onError(new Error('Unknown error occurred'));
    }
  }
};

// Usage

  name: string;
  email: string;

  url: '/api/users/123',

  },
  onError: (error) => {
    console.error(error.message); // Type-safe: error is Error

#### 6\. Type-Safe Error Handling

Properly type error handlers to ensure safe method access.

```typescript
// ✅ DO: Type-safe error handling
// File: error-handler.util.ts

type ErrorHandler = (error: Error) => void;

type TryCatchArgs<T> = {
  operation: () => T;
  onError: ErrorHandler;
  fallbackValue: T;
};

export const tryCatch = <T>({ operation, onError, fallbackValue }: TryCatchArgs<T>): T => {

      onError(error); // Type-safe: onError expects Error
    } else {
      onError(new Error('Unknown error'));
    }
    return fallbackValue;
  }
};

  operation: () => JSON.parse('invalid json'),
  onError: (error) => console.error(error.message), // Type-safe
  fallbackValue: null,
});
```

#### 7\. Type-Safe Dynamic Method Calls

When calling methods dynamically, ensure type safety through proper typing.

```typescript
// ✅ DO: Type-safe dynamic method invocation
// File: method-invoker.util.ts

type MethodMap = {
  [key: string]: (...args: unknown[]) => unknown;
};

type InvokeMethodArgs<T extends MethodMap> = {
  methods: T;
  methodName: keyof T;
  args: unknown[];
};

export const invokeMethod = <T extends MethodMap>({
  methods,
  methodName,
  args,
}: InvokeMethodArgs<T>): unknown => {
  const method = methods[methodName];

  if (typeof method !== 'function') {
    throw new Error(`Method ${String(methodName)} is not a function`);
  }

  return method(...args); // Type-safe: method is verified as function
};

// Usage
const calculatorMethods = {
  add: (a: number, b: number) => a + b,
  subtract: (a: number, b: number) => a - b,
  multiply: (a: number, b: number) => a * b,
};

const result = invokeMethod({
  methods: calculatorMethods,
  methodName: 'add',
  args: [5, 3],
});
```

```typescript
// ✅ DO: Type-safe method calls with validation
// File: safe-method-call.util.ts

type SafeMethodCallArgs<T, K extends keyof T> = {
  object: T;
  methodName: K;
  args: unknown[];
};

export const safeMethodCall = <T, K extends keyof T>({
  object,
  methodName,
  args,
}: SafeMethodCallArgs<T, K>): unknown => {
  const method = object[methodName];

  if (typeof method !== 'function') {
    throw new Error(`${String(methodName)} is not a method`);
  }

  return (method as Function).apply(object, args); // Type-safe with validation
};

  fn: (a: number, b: number) => a + b,
  args: [5, 3], // Type-checked: must be [number, number]
}); // result is inferred as number
```

### 📝 Summary of Dos and Don'ts

#### ✅ DO:

**Type Safety**

- Always explicitly type function parameters, especially callbacks
- Use type guards to narrow `unknown` types before calling methods
- Create custom type predicates for complex validation
- Use generic constraints to ensure required methods exist
- Validate API responses before accessing properties or methods
- Check for null/undefined before calling methods on optional properties

**Error Handling**

- Type error handlers explicitly as `(error: Error) => void`
- Use `instanceof Error` checks when catching errors
- Validate runtime data before making assumptions about its shape
- Provide meaningful error messages when type validation fails

**Best Practices**

- Prefer `unknown` over `any` - it forces you to validate types
- Use optional chaining (`?.`) for safe property access
- Create reusable type guards for common validations
- Document why type assertions are safe when you must use them
- Use generic constraints to enforce type contracts

**React/UI**

- Type event handlers explicitly (e.g., `React.FormEvent<HTMLFormElement>`)
- Check optional callbacks exist before calling them
- Type component props thoroughly, especially callback props
- Use proper types for refs and context values

#### ❌ DON'T:

**Dangerous Practices**

- Don't use `any` type for values you'll call as functions
- Don't call methods on `unknown` without type guards
- Don't use type assertions (`as`) without runtime validation
- Don't call optional callbacks without checking they exist
- Don't assume API responses match expected types
- Don't call methods without checking for null/undefined

**Anti-Patterns**

- Don't disable TypeScript checks with `@ts-ignore` or `@ts-expect-error` for unsafe calls
- Don't use the generic `Function` type - use specific signatures
- Don't rely solely on type assertions for safety
- Don't skip runtime validation for external data
- Don't use `any` to "fix" type errors quickly
- Don't chain method calls on potentially undefined values

**Common Mistakes**

- Don't forget to check if optional properties exist before using them
- Don't assume external data matches your TypeScript types
- Don't use type assertions to bypass necessary validations
- Don't call methods on union types without narrowing first
- Don't ignore TypeScript errors about unsafe calls

| Unknown callback  | callback(...)           | if (typeof callback === 'function') callback(...) |
| API response      | data.user.name          | Validate with type guard, then access             |

### 🔍 Type Guard Patterns

#### Basic Type Guards

```typescript
// ✅ Function check
const isFunction = (value: unknown): value is Function => {
  return typeof value === 'function';
};

// ✅ Object check
const isObject = (value: unknown): value is Record<string, unknown> => {
  return typeof value === 'object' && value !== null;
};

// ✅ Array check
const isArray = (value: unknown): value is unknown[] => {
  return Array.isArray(value);
};

// ✅ String check
const isString = (value: unknown): value is string => {
  return typeof value === 'string';
};

// ✅ Number check
const isNumber = (value: unknown): value is number => {
  return typeof value === 'number' && !isNaN(value);
};
```

#### Complex Type Guards

```typescript
// ✅ Check for specific method
const hasMethod = <K extends string>(
  value: unknown,
  methodName: K,
): value is Record<K, Function> => {
  return (
    typeof value === 'object' &&
    value !== null &&
    methodName in value &&
    typeof (value as any)[methodName] === 'function'
  );
};

// Usage
if (hasMethod(obj, 'toString')) {
  obj.toString(); // Type-safe
}
```

```typescript
// ✅ Check for callback signature
type StringCallback = (value: string) => string;

const isStringCallback = (value: unknown): value is StringCallback => {
  if (typeof value !== 'function') {
    return false;
  }

  // Optional: test the function if safe to do so
  try {
    const result = value('test');
    return typeof result === 'string';
  } catch {
    return false;
  }
};

// Usage
if (isStringCallback(callback)) {
  const result = callback('hello'); // Type-safe
}
```

```typescript
// ✅ Safe property access
type SafeGetArgs<T, K extends keyof T> = {
  object: T;
  key: K;
  fallback: T[K];
};

export const safeGet = <T, K extends keyof T>({
  object,
  key,
  fallback,
}: SafeGetArgs<T, K>): T[K] => {
  const value = object[key];
  return value !== undefined && value !== null ? value : fallback;
};
```

```typescript
// ✅ Safe method call
type SafeCallArgs<T> = {
  object: unknown;
  methodName: string;
  args: unknown[];
  fallback: T;
};

export const safeCall = <T>({ object, methodName, args, fallback }: SafeCallArgs<T>): T => {
  if (typeof object !== 'object' || object === null) {
    return fallback;
  }

  const method = (object as any)[methodName];

  if (typeof method !== 'function') {
    return fallback;
  }

  try {
    return method.apply(object, args);
  } catch {
    return fallback;
  }
};
```

```typescript
// ✅ Safe callback execution
type SafeExecuteArgs<T, R> = {
  callback: unknown;
  args: T[];
  fallback: R;
};

export const safeExecute = <T, R>({ callback, args, fallback }: SafeExecuteArgs<T, R>): R => {
  if (typeof callback !== 'function') {
    return fallback;
  }

  try {
    return callback(...args);
  } catch {
    return fallback;
  }
};
```

#### Pattern 5: Error Boundary with Type Safety

```typescript
// ✅ DO: Type-safe error handling
type ErrorHandler = (error: Error, errorInfo: React.ErrorInfo) => void;

type ErrorBoundaryProps = {
  children: React.ReactNode;
  onError?: ErrorHandler;
  fallback: React.ReactNode;
};

export class ErrorBoundary extends React.Component<ErrorBoundaryProps> {
  state = { hasError: false };

  static getDerivedStateFromError() {
    return { hasError: true };
  }

  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    // Type-safe: error is Error, errorInfo is React.ErrorInfo
    if (this.props.onError) {
      this.props.onError(error, errorInfo); // Type-safe call
    }
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback;
    }

    return this.props.children;
  }
}
```

### 🎓 Learning Path: From Unsafe to Safe

#### Level 1: Basic Type Safety

```typescript
// ❌ Unsafe
const execute = (fn: any) => fn();

// ✅ Safe
const execute = (fn: () => void): void => fn();
```

#### Level 2: Optional Parameter Checks

```typescript
// ❌ Unsafe
const execute = (fn?: Function) => fn();

// ✅ Safe
const execute = (fn?: () => void): void => {
  if (fn) fn();
};
```

#### Level 3: Unknown Type Guards

```typescript
// ❌ Unsafe
const execute = (fn: unknown) => (fn as Function)();

// ✅ Safe
const execute = (fn: unknown): void => {
  if (typeof fn === 'function') fn();
};
```

#### Level 4: Generic Type Constraints

```typescript
// ❌ Unsafe
const call = <T>(obj: T, method: string) => (obj as any)[method]();

// ✅ Safe
type WithMethod<K extends string> = Record<K, () => void>;

const call = <K extends string>(obj: WithMethod<K>, method: K): void => {
  obj[method]();
};
```

#### Level 5: Complex Validation

```typescript
// ❌ Unsafe
const process = (data: unknown) => {
  return (data as any).items.map((item: any) => item.name);
};

// ✅ Safe
type DataWithItems = {
  items: Array<{ name: string }>;
};

const isDataWithItems = (value: unknown): value is DataWithItems => {
  if (typeof value !== 'object' || value === null) return false;
  const obj = value as Record<string, unknown>;
  return (
    Array.isArray(obj.items) &&
    obj.items.every(
      (item) => typeof item === 'object' && item !== null && typeof (item as any).name === 'string',
    )
  );
};

const process = (data: unknown): string[] => {
  if (!isDataWithItems(data)) {
    throw new Error('Invalid data structure');
  }
  return data.items.map((item) => item.name); // Type-safe
};
```
