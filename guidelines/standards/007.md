## 💻 Code Standard: Type-Safe Function and Method Calls

### 🎯 Objective

To prevent runtime errors by ensuring all function and method calls are type-safe. This standard prohibits calling functions or methods on values typed as `any`, `unknown`, or other unsafe types without proper type checking. By enforcing explicit typing and type guards, we ensure that all function calls are verified by TypeScript's type system, preventing crashes and improving code reliability.

### 📜 Rule Details

1.  **No `any` Type Calls:** Never call a function or method on a value typed as `any`. Always provide explicit types.

2.  **No `unknown` Type Calls:** Never call a function or method on a value typed as `unknown` without first narrowing the type using type guards.

3.  **Proper Return Type Annotation:** All functions that return callable values must have explicit return types that are not `any` or `unknown`.

4.  **Type Guards Required:** When dealing with dynamic or external data, use type guards to verify the value is callable before invoking it.

5.  **Chain Call Safety:** When chaining method calls, ensure each intermediate value has proper typing to prevent unsafe calls in the chain.

6.  **Array Method Safety:** When using array methods like `.map()`, `.filter()`, `.reduce()`, ensure the callback and intermediate values are properly typed.

### 🔍 What is an Unsafe Call?

An unsafe call occurs when:

- Calling a method on a value of type `any` or `unknown`
- Calling a function returned from an untyped source
- Chaining methods where intermediate values lack proper types
- Using array methods on arrays with `any` elements
- Calling properties on objects without type verification

### ✅ Required Code Snippets (The "Do")

#### 1\. Properly Type Function Returns

Always explicitly type function return values to avoid `any` propagation.

```typescript
// ✅ DO: Explicitly type return values
// File: string-operations.util.ts

type TransformStringArgs = {
  value: string;
  operations: Array<(s: string) => string>;
};

export const transformString = ({ value, operations }: TransformStringArgs): string => {
  // Explicit return type prevents 'any' propagation
  return operations.reduce((result, operation) => operation(result), value);
};

// Usage - all calls are type-safe
const result = transformString({
  value: 'hello',
  operations: [
    (s) => s.toUpperCase(), // Type-safe: s is string
    (s) => s.trim(), // Type-safe: s is string
    (s) => s.slice(0, 3), // Type-safe: s is string
  ],
});
```

```typescript
// ✅ DO: Type array transformations explicitly
// File: array-transform.util.ts

type TransformArrayArgs<T, U> = {
  items: T[];
  transformer: (item: T) => U;
};

export const transformArray = <T, U>({ items, transformer }: TransformArrayArgs<T, U>): U[] => {
  // Explicit generic types ensure type safety
  return items.map((item) => transformer(item));
};
```

#### 2\. Type Guards for Dynamic Values

Use type guards to verify callable values before invocation.

```typescript
// ✅ DO: Use type guards for unknown callable values
// File: safe-invoke.util.ts

const isFunction = (value: unknown): value is (...args: unknown[]) => unknown => {
  return typeof value === 'function';
};

type SafeInvokeArgs = {
  callback: unknown;
  args: unknown[];
  fallback?: unknown;
};

export const safeInvoke = ({ callback, args, fallback }: SafeInvokeArgs): unknown => {
  if (!isFunction(callback)) {
    return fallback;
  }

  // Type-safe: callback is verified as a function
  return callback(...args);
};
```

```typescript
// ✅ DO: Create specific type guards for method calls
// File: object-method-caller.util.ts

type ObjectWithMethod = {
  method: (...args: unknown[]) => unknown;
};

const hasMethod = (value: unknown, methodName: string): value is ObjectWithMethod => {
  return (
    typeof value === 'object' &&
    value !== null &&
    methodName in value &&
    typeof (value as Record<string, unknown>)[methodName] === 'function'
  );
};

type CallMethodArgs = {
  object: unknown;
  methodName: string;
  args: unknown[];
};

export const callMethod = ({ object, methodName, args }: CallMethodArgs): unknown => {
  if (!hasMethod(object, methodName)) {
    throw new Error(`Object does not have method: ${methodName}`);
  }

  // Type-safe: method existence is verified
  return object.method(...args);
};
```

#### 3\. Type String Method Chains Properly

Ensure intermediate values in method chains have proper types.

```typescript
// ✅ DO: Type each step in method chains
// File: text-processor.util.ts

type ProcessTextArgs = {
  text: string;
  shouldTrim: boolean;
  shouldUppercase: boolean;
};

export const processText = ({ text, shouldTrim, shouldUppercase }: ProcessTextArgs): string => {
  // Each step has explicit type
  let result: string = text;

  if (shouldTrim) {
    result = result.trim(); // Type-safe: result is string
  }

  if (shouldUppercase) {
    result = result.toUpperCase(); // Type-safe: result is string
  }

  return result;
};
```

```typescript
// ✅ DO: Type array method chains with generics
// File: filter-and-map.util.ts

type FilterAndMapArgs<T, U> = {
  items: T[];
  predicate: (item: T) => boolean;
  mapper: (item: T) => U;
};

export const filterAndMap = <T, U>({ items, predicate, mapper }: FilterAndMapArgs<T, U>): U[] => {
  // Type-safe chain: T[] -> T[] -> U[]
  return items
    .filter((item) => predicate(item)) // Type-safe: item is T
    .map((item) => mapper(item)); // Type-safe: item is T
};
```

#### 4\. Avoid `any` in Array Operations

Always type array elements explicitly, especially in transformations.

```typescript
// ✅ DO: Explicitly type array elements
// File: parse-values.util.ts

type ParsedValue = {
  id: string;
  value: number;
};

type ParseValuesArgs = {
  rawData: string[];
};

export const parseValues = ({ rawData }: ParseValuesArgs): ParsedValue[] => {
  // Explicit typing prevents 'any' propagation
  return rawData
    .map(
      (raw: string, index: number): ParsedValue => ({
        id: `item-${index.toString()}`,
        value: Number.parseInt(raw, 10),
      }),
    )
    .filter((item: ParsedValue) => !Number.isNaN(item.value));
};
```

```typescript
// ✅ DO: Type reduce operations explicitly
// File: aggregate-data.util.ts

type DataItem = {
  category: string;
  value: number;
};

type AggregateResult = Record<string, number>;

type AggregateDataArgs = {
  items: DataItem[];
};

export const aggregateData = ({ items }: AggregateDataArgs): AggregateResult => {
  // Explicit accumulator type ensures type safety
  return items.reduce<AggregateResult>((acc, item) => {
    const current = acc[item.category] ?? 0;
    acc[item.category] = current + item.value;
    return acc;
  }, {});
};
```

#### 5\. Type External API Responses

Always type API responses and verify before calling methods.

```typescript
// ✅ DO: Type and validate API responses
// File: api-client.util.ts

type ApiResponse<T> = {
  data: T;
  status: number;
};

type User = {
  id: string;
  name: string;
  email: string;
};

const isUser = (value: unknown): value is User => {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    'name' in value &&
    'email' in value &&
    typeof (value as User).id === 'string' &&
    typeof (value as User).name === 'string' &&
    typeof (value as User).email === 'string'
  );
};

type FetchUserArgs = {
  userId: string;
};

export const fetchUser = async ({ userId }: FetchUserArgs): Promise<User> => {
  const response = await fetch(`/api/users/${userId}`);
  const data: unknown = await response.json();

  // Validate before using
  if (!isUser(data)) {
    throw new Error('Invalid user data');
  }

  // Type-safe: data is verified as User
  return data;
};
```

### ❌ Anti-Patterns (The "Don't")

#### 1\. Calling Methods on `any` Type

```typescript
// ❌ DON'T: Call methods on 'any' type
// File: string-utils.util.ts (WRONG)

export const toPascalCase = (value: string): string => {
  // ❌ WRONG: Implicit 'any' in method chain
  return value
    .split(/[^a-zA-Z0-9]+/)
    .filter(Boolean)
    .map((part) => part.charAt(0).toUpperCase() + part.slice(1))
    .join('')
    .replaceAll(/[^a-zA-Z0-9]/g, '') // Unsafe call on error type
    .replace(/^\d+/, '');
};
```

**Why it's wrong:**

- The method chain returns an error type due to missing type annotations
- Calling `.replaceAll()` and `.replace()` on an error type is unsafe
- Type safety is lost in the transformation chain

**How to fix:**

```typescript
// ✅ CORRECT: Explicitly type each step
export const toPascalCase = (value: string): string => {
  const parts: string[] = value.split(/[^a-zA-Z0-9]+/).filter(Boolean);
  const capitalized: string = parts
    .map((part: string) => part.charAt(0).toUpperCase() + part.slice(1))
    .join('');
  const cleaned: string = capitalized.replace(/[^a-zA-Z0-9]/g, '');
  const result: string = cleaned.replace(/^\d+/, '');
  return result;
};
```

#### 2\. Calling Unknown Functions Without Guards

```typescript
// ❌ DON'T: Call unknown functions directly
// File: callback-executor.util.ts (WRONG)

type ExecuteCallbackArgs = {
  callback: unknown;
  data: unknown;
};

export const executeCallback = ({ callback, data }: ExecuteCallbackArgs): unknown => {
  // ❌ WRONG: Calling unknown value without type check
  return callback(data);
};
```

**Why it's wrong:**

- `callback` is `unknown` and may not be a function
- No type verification before calling
- Will crash at runtime if `callback` is not callable

**How to fix:**

```typescript
// ✅ CORRECT: Use type guard
const isFunction = (value: unknown): value is (arg: unknown) => unknown => {
  return typeof value === 'function';
};

export const executeCallback = ({ callback, data }: ExecuteCallbackArgs): unknown => {
  if (!isFunction(callback)) {
    throw new Error('Callback must be a function');
  }
  return callback(data); // Type-safe
};
```

#### 3\. Unsafe Array Method Chains

```typescript
// ❌ DON'T: Use array methods without proper typing
// File: data-processor.util.ts (WRONG)

type ProcessDataArgs = {
  data: unknown[];
};

export const processData = ({ data }: ProcessDataArgs) => {
  // ❌ WRONG: data is unknown[], calling methods is unsafe
  return data
    .filter((item) => item)
    .map((item) => item.toString())
    .join(', ');
};
```

**Why it's wrong:**

- Array elements are `unknown`, so calling methods is unsafe
- No guarantee that elements have `.toString()` method
- Type safety is completely lost

**How to fix:**

```typescript
// ✅ CORRECT: Type the array properly or use type guards
type ProcessDataArgs = {
  data: string[];
};

export const processData = ({ data }: ProcessDataArgs): string => {
  return data
    .filter((item: string) => item.length > 0)
    .map((item: string) => item.trim())
    .join(', ');
};
```

#### 4\. Unsafe Property Access and Calls

```typescript
// ❌ DON'T: Call properties without type verification
// File: object-invoker.util.ts (WRONG)

type InvokeMethodArgs = {
  object: Record<string, unknown>;
  methodName: string;
};

export const invokeMethod = ({ object, methodName }: InvokeMethodArgs): unknown => {
  // ❌ WRONG: Calling unknown property as function
  return object[methodName]();
};
```

**Why it's wrong:**

- Property value is `unknown`, may not be a function
- No type checking before invocation
- Runtime error if property doesn't exist or isn't callable

**How to fix:**

```typescript
// ✅ CORRECT: Verify property is callable
export const invokeMethod = ({ object, methodName }: InvokeMethodArgs): unknown => {
  const method = object[methodName];

  if (typeof method !== 'function') {
    throw new Error(`Property ${methodName} is not a function`);
  }

  return method(); // Type-safe after verification
};
```

#### 5\. Chaining Without Type Safety

```typescript
// ❌ DON'T: Chain methods on untyped values
// File: transform-chain.util.ts (WRONG)

type TransformArgs = {
  input: unknown;
};

export const transform = ({ input }: TransformArgs) => {
  // ❌ WRONG: Chaining on unknown type
  return input.toString().trim().toUpperCase().split(' ');
};
```

**Why it's wrong:**

- `input` is `unknown`, calling `.toString()` is unsafe
- Entire chain is built on unsafe foundation
- No guarantee methods exist

**How to fix:**

```typescript
// ✅ CORRECT: Verify type before chaining
export const transform = ({ input }: TransformArgs): string[] => {
  if (typeof input !== 'string' && typeof input !== 'number') {
    throw new Error('Input must be string or number');
  }

  const str: string = String(input);
  return str.trim().toUpperCase().split(' ');
};
```

### 📋 Safe Calling Checklist

Before making any function or method call, verify:

- ✅ Is the value properly typed (not `any` or `unknown`)?
- ✅ If using `unknown`, have I used a type guard?
- ✅ Are all function parameters explicitly typed?
- ✅ Is the return type explicitly declared?
- ✅ In method chains, is each intermediate value typed?
- ✅ For array operations, are element types explicit?
- ✅ For external data, have I validated the structure?

### 🎯 Summary

- **Always** provide explicit types for function parameters and return values
- **Always** use type guards when calling methods on `unknown` values
- **Always** verify callable values before invocation
- **Always** type intermediate values in method chains
- **Never** call methods on `any` or `unknown` without type checking
- **Never** rely on implicit typing in complex operations
- **Never** assume external data has the correct structure
